# 鸿蒙全场景策略：在日常入口接回同一项工作

日期：2026-11-01。配套 [审查](COMPETITION_AGENT_PRODUCT_AUDIT.md)、[冲刺](COMPETITION_SPRINT_ROADMAP.md)、[真实旅程](COMPETITION_REAL_USER_JOURNEY.md)。鸿蒙是正常产品的一部分，不是Web缩小版，也不做比赛专用系统入口。本轮使用harmonyos-design审视方法，所有项目数值/层级建议属于H4 House Style，不冒充华为强制规则。

## 1. 已知与假设

| 上下文项 | 本轮事实 / 未知 |
|---|---|
| 目标 | 手机快速采集、补一项条件、纠正与停止；卡片看到主关注；Web深入证据和预算 |
| 声明设备 | module.json5：phone、tablet、2in1；无wearable声明 |
| 平台 | 原快照只读查询模拟器API24、OpenHarmony6.1.1.125；当前未重连或安装，新设备身份未知 |
| SDK | 已安装DevEco default SDK；ShareExtensionAbility声明since10；HMS insightIntent有未登记错误1000101101与版本要求 |
| 输入/窗口 | 源码手机触摸为主；平板/2in1声明不等于键盘、分屏、折叠屏均已验收 |
| 主题/字号/无障碍 | 有浅/深主题tokens与历史图片；本轮未运行读屏、大字体、快速操作或帧率测试 |
| 网络/包 | Constants源码review目标为公开HTTPS后端；公开release71499b6；当前实际安装包hash/签名未知 |
| 可用图像 | 10/31 focus、CT7撤销、11/01项目/设置截图；有历史合成账号/来源，非新业务操作签收 |

以下策略不以模拟器API级别推定商业HarmonyOS服务开通；本地SDK是签名与类型依据，官方概览是能力类别依据，实际可用由目标设备/签名/服务登记决定。

## 2. 各端承担不同任务

| 端 | 适合做什么 | 不应承诺什么 | 原对象与验收 |
|---|---|---|---|
| 手机 | 捕获材料、短回应、纠正、查看重要变化；登录App可审阅明确操作 | 手机常驻运行服务器Worker、所有内容完全离线、无条件自动批准 | 原Capture/Attachment、Conversation/question、Mission/审批；冷/热启动与原身份读回 |
| 桌面卡片 | 一项主关注、必要等待/变化、上次同步、进入原任务 | 缩小项目列表、完整证据审查、卡片直接审批、已读即执行 | FormExtension/WidgetDataService原快照与TTL，点开重鉴权 |
| Web | 长文/原页、动态调查与证据、责任/预算、实际提案批准、成果与结果核查 | 自动拥有手机/小艺没有的更宽业务授权 | 同一后端原Mission/来源/Action/resultCardId |
| 平板/2in1 | 资料与讨论并看、手写/键鼠辅助深读（实际支持后） | 仅放大手机界面就称多端优化；不经验证宣称跨设备迁移 | 原页面自适应，触摸/键盘/窗口独立验收；当前先保兼容 |
| 小艺 | 查询状态、脱敏摘要、打开原Mission、获准低风险只读接续 | 替用户批准、扩大scope、口头“继续”自动写外部对象 | 现有authorizeXiaoyiMission/inspect/resume，平台身份与投递另验 |
| 手表 | 长期可研究一项脱敏关注/回手机入口 | 当前已支持、完整审批、浏览私有材料、后台Agent | 无manifest/页面/设备证据；S3条件化研究，不进本次已交付清单 |

去掉鸿蒙不会让服务器无法执行任务；损失的是材料出现处的捕获、卡片发现和随时回应。去掉Web也不应切断原任务，但复杂证据/授权核查成本可能上升。这些差异用操作时间、错误与用户理解测量，不能靠设备数量推导。

## 3. 服务卡片：当前情况与最小增量

已有 `EntryFormAbility.ets`、2×2/2×4规格、本地持久化及路由，`onUpdateForm`当前重读缓存，不是无限网络后台。WidgetDataService已有owner、project、session、generation检查，Mission snapshot到期取会话期限与5分钟的较早者；不能说卡片完全没有安全边界。

首屏优先级：需要用户处理的一项原问题/审批或高价值变化 → 当前主焦点 → 正在跟进的原责任。只显示本卡容量能表达的一项，2×4可加一句原责任状态和同步时间，不把三个技术模块挤进每张卡。没有重要变化时显示最后实际观察/同步与入口，不生成“新发现”。

注意两种时钟：Widget的updatedAt是本地同步时间，不等于来源observedAt。同步、实际检查、新鲜度分别读回；过期、离线、退出登录与服务不可用有不同状态，旧个人信息不留在卡片上。原快照已失效时不展示私有标题来诱导点击。系统更新频率与后台寿命以真实设备测量，不承诺分钟级必达。

点卡片传原project/mission/question或source身份与版本意图，接收App再读取当前对象。旧问题已答显示原结果/后继；旧审批过期返回实际待处理，不自动确认。重复点击不新建任务，不改变已读/批准/执行记录。推送、卡片展示、平台接受、用户看到、业务批准和实际执行始终分开。

**实际增量**是精确原问题与新鲜度，不是新增Form框架。回滚可退到原项目/任务入口并清除敏感缓存；后端责任仍在原Worker，无需App另起执行器。

## 4. 手机与Web精确接续

原 `EntryAbility.onCreate/onNewWant` 可解析projectId/missionId，原 `lib/continuity/handoff.ts`、`lib/conversation/entry.ts` 与readback负责原任务身份。扩展最小导航信封：定位意图、原对象ID、相关revision和expiry；不得携带批准令牌、个人原文、私有query或任意外部URL。

手机在当前对话看到一个具体问题，短答绑定questionId/原版本/稳定请求。Web从同一委托继续，能回原文和已做步骤；用户改变目标后原generation/lease守卫决定能否派发/发布，端侧“显示新版本”不是正确性的替代。

登录后恢复待打开意图须owner绑定；换账号、对象删除、撤权或权限不符拒绝并提供安全返回。若旧提案已失效，显示原因并回当前原提案，不能把历史链接当作同意。系统级跨设备迁移需要onContinue/continueManager及两台设备验证，目前普通共享后端接续不冒充该能力。

## 5. 系统分享与离线捕获

当前module没有分享接收skill/ShareExtensionAbility业务入口。原Attachment类型支持图片/PDF/文件与解析状态，不代表新音频/任意格式可用。先做真机技术探针，验证分享扩展注册、临时URI可读性/授权期限、冷/热启动和取消。

建议首个完整范围：文本/URL/一个受支持文件，截图按图片原件处理。流程是系统分享→owner隔离草稿/必要原件落盘→用户核对项目归属/材料理解→确认→原Capture/Attachment幂等同步。项目建议不是写入授权；URL文本不自动Fetch，图片不默认已OCR，材料中的命令不进入永久目标。未登录先暂存最小内容并说明归属未确认，不把上一账号项目作为默认。

离线只保证已落盘的数据及可恢复原件，空间不足/URI过期如实失败；原件尚不可持久保存时不能说“已保存”。联网后重新鉴权/处理许可，前台有界同步；退出/撤权/删除、回包未知及同requestId换载荷都走原守卫。新增云OCR/embedding/识别需明确许可与原计量，不为了分享入口扩大处理范围。

11/05平台探针通过且不挤压S0/S1时进入S2交付；否则保留应用内采集并标系统分享待验。不是取消低摩擦采集长期目标，也不是为拍摄加入一个假分享按钮。

## 6. 小艺与Intents：三层能力不能混淆

| 层 | 当前证据 | 允许说法 |
|---|---|---|
| 业务后端 | inspectMissionFromXiaoyi返回原Mission及OPEN_MISSION意图；resume仅获准LOW_RISK_READ_ANALYZE/READ_ANALYZE且预算未耗尽 | 有受鉴权查询与受限接续适配，不等于已接入平台 |
| SDK/声明 | 本地ShareExtensionAbility、FormProvider、insightIntent、continueManager API；module缺实际Intents业务注册 | 有接入探针基础，不等于签名/服务/分发可用 |
| 平台/设备 | 当前设置截图明确“尚未接入”；无本轮注册/投递/真机回执 | 平台能力未验收，不展示伪成功或语音审批 |

华为官方Intents概览列有习惯/事件/位置推荐、技能调用和本地搜索，说明潜在渠道，不保证当前应用获得推荐或执行资格。[Intents Kit](https://developer.huawei.com/consumer/cn/sdk/intents-kit)。本轮本机SDK声明中未登记错误1000101101与版本要求也说明不能仅靠HTTP后端替代平台接入。

首个可行目标是“查看当前关注/打开原Mission”，再考虑已批准只读接续。需要核对目标设备/系统、开发者账户、应用签名/bundle、服务登记与配额、平台身份到原owner映射、失败/撤权与App返回。分享或投递到平台的内容本身是外发，不因只是摘要就默认可用。动作批准回登录App；手表/语音不拿新的批准权。

**审视结论：有条件通过，范围限于方向与已有图像/源码。** 当前没有目标真机、完整返回、辅助输入与性能签收，不能宣布鸿蒙产品全部验收。需要下一节矩阵关闭适用Major；未知项保持待验证。

## 9. 投入裁决

优先三项自然交互：**卡片到原问题、手机短回应/纠正与Web证据接续、真实材料分享并确认归属**。前两项基于大量现有代码，分享须平台探针通过。小艺作为条件化增强并非必需的主线门票；平板以原任务自适应验证为先，穿戴和系统迁移留S3。

鸿蒙差异化不在于控件长得不同，而在于上述入口能减少找回上下文与重复解释，并保持同一授权/结果身份。它需要与Agent真实决策一起验证；不能让平台接入数量替代用户收益，也不能因为Agent赛道而忽略手机的核心旅程。
