# 全国总决赛：正常产品的真实使用与证据旅程

日期：2026-11-01。配套 [审查](COMPETITION_AGENT_PRODUCT_AUDIT.md)、[冲刺](COMPETITION_SPRINT_ROADMAP.md)、[原V01～V40验收](../PRODUCT_VALUE_TRUST/FINAL_VERTICAL_ACCEPTANCE_JOURNEY_2026-11-01.md)。下面是待执行协议，不是已完成用户实验；不设计演示模式、任务模板执行器或“漂亮轨迹生成器”。

## 1. 先选真实需要，不选容易剪辑的场景

| 候选场景 | 长期条件 / 自主调查 | 持续变化 / 责任 | 鸿蒙实际减负 | 可核对结果与迁移性 | 裁决 |
|---|---|---|---|---|---|
| 软件工程项目 | 版本、历史问题、CI与环境条件 | 提交、CI、发布与待验路径 | 途中记问题、看关键变化、回原排查 | 固定版本日志/用户路径/实际结果；可迁移到课程开发 | **主场景A**，可以ProjectMemo自身准备为真实项目之一 |
| 学生科研课题 | 数据/方法条件、原文、旧假设与反例 | 新实验/材料修订，非固定周期 | 手机补实验条件、纠正方法，Web深读 | 原数据/实验协议/实际结果；论文结论不能替本实验 | **主场景B**，须由真实参与者提供，不虚构科研资料 |
| 多阶段课程项目 | 要求变化、知识依赖和提交 | 里程碑/材料/作业反馈 | 分享PDF、随手记录、短回应 | 真实要求与交付回执，易迁移 | 科研资料不具条件时作为第二类真实项目；不能用改名软件样例替代 |
| 一般个人收集 | 偏好/归属，调查需求不稳定 | 未必有长期责任 | 捕获有价值 | 没有目标就不硬建Mission | 长期拓展，不能为凑Always On强设委托 |
| 专门制作的比赛脚本 | 内容能被预排，但无真实需求保证 | 人为注入变化 | 只便于拍摄 | 无通用性证据 | 不采用 |

A/B不是产品内模板名，也不固定工具序列。研究者在执行前冻结两类真实项目的owner、材料时间点、真实问题和验收条件。ProjectMemo自身的问卷、发布、设备验收可作A的真实任务，不在产品里硬编码11/12、竞赛项目名或题目关键字。尚无B材料和同意时记“待招募/待提供”，不算跨项目通过。

## 2. 入场条件与许可

先关闭适用Security Gate，再使用真实私人材料。记录源码/dirty/两端包/后端release、数据库环境、owner/member、材料原件/hash及使用同意。真实部署、模型付费、工具外写各有具体授权与上界；本协议不自动获得授权。

所有模型、工具、HTTP、协议修复、OCR/embedding与评审调用计量；未知请求保留原预占。价格不明时用已实现资源上限，不捏造金额封顶。外部服务读权限与个人云处理分开，敏感query不从私有背景自动拼接。角色/期限/工具和成功条件沿原责任预览，用户确认业务对象及后续Action分别办理。

本轮已观察线上release71499b6、本地1ee、PMcf不一致。正式旅程必须先冻结一致且有签收的客户端/后端组合；不能直接在旧线上账号测试新PM迁移，不能为方便清空原App或真实数据库。

## 3. A：一项真实软件任务怎样自然展开

### D1，得到材料或发现问题

用户收到真实要求、看到某次失败或记录一个实际设备问题。从原App粘贴/选材开始；系统分享只有完成平台验收后才纳入正式分享轨。未实现的渠道不伪装成已支持。离线先显示已落盘草稿/原件，联网后重新鉴权和选择项目归属。

已有项目回到原记录；新项目进入FVT01整体理解预览，原文陈述、建议目标、约束、未知和下一方向各有来源身份。用户可修改“先查目标设备可用性，不是先追求指标”，接受后才持久化有效项目/目标及原采集对象。原账户会话和临时文件只是受控预览轨迹。回包丢失按原身份恢复，不重复建立项目。

### D1，查清眼前问题

用户用自己的话表达真实问题。Agent依已有证据可以直接回答，也可回原文件/旧决定、读固定CI或获准环境；私人条件缺失时提出最有区分力的一项问题；许可不够则请求具体范围；预算不足或资料无法验证可停。

实际有新观察时，它应能改变下一步。例如真实CI状态与设备/服务响应不一致，就核对各自版本和覆盖；如果根本没有这种不一致，不人为制造一份“新发现”。原Memory/Dream只在当前问题适用时参与；不要求每轮新建假设或检索所有工具。

记录原run/step、原始工具输入输出指针、模型身份、来源版本、预算与缺口。独立核对结论是否被原文支持，而不只看页面文案流畅。现有材料已足够，零外部工具调用也可能是正确决策。

### D1，选择是否交代长期责任

用户可以拒绝持续委托，仍得到一次有价值调查。愿意交代时，用自然表达说明希望关注的对象和结束条件；原预览呈现范围、工具、检查条件、期限、累计预算、审批及停止方式，复杂参数渐进展开。

确认后原Mission承接同一问题，不另生一个后台副本。用户关闭App和Web；由原服务器Worker继续，记录实际scan/claim/observation，不能把保存任务或heartbeat算作调查已发生。任务没有到检查时间时显示未到期，不假装已查。

### D2，真实变化、无变化或失败

按照实际发生情况记账：

- 无重要变化：可以有获准元数据请求，但不重复叫模型和通知；观察时间更新不当作新发现。
- 有新版本/失败/相关证据：原GoalGap/Hypothesis重核，动态决定继续调查、建议或问用户，不固定执行顺序。
- 网络/权限/来源失败：记失败或失效及退避；不能说“没有变化”。
- 等待用户：保留原问题与责任，不反复唤醒、催促或自填答案。

如果真实三日没有出现上述全部事件，其余只在隔离故障轨验证。禁止为了凑剧情修改公开CI、伪造日志、临时seed一条通知或安排预设模型回答。

### D2，手机处理一项必要协作

卡片/App正常入口显示一项主关注及当前同步时间；点开原question/source。用户补充设备条件、纠正目标、暂停或表示自己接管；Web随后回同一mission/turn/question看到新版本。已读不变批准，用户报告已做完仍是报告，必要时继续核实。

“这次简短”“本周本项目只提醒阻塞”“以后技术讨论先给结论”进入不同原准入/策略范围；局部与账户偏好不混用。云处理关闭不因已有项目许可被绕过。时间越界无新事件时，原派发/发布守卫也须核对。

### D3，Web核查并留下真实结果

用户查看短进展叙事：上次以来发生什么、支持到哪里、现在先处理什么。展开到原来源/反例/条件、原活动和用量，不开独立评委台。

需要行动时，Agent沿原预览提出，由用户批准后创建真实Action；实际操作后用原完成服务写resultCardId。独立设备或产物检查与用户报告分列；草稿存在、CI绿、工具成功都不能单独证明现实目标达成。结果可以失败或UNKNOWN，价值在于明确缩小问题及可靠保留责任。

新会话问“还差什么”，读回原目标、问题、结果和等待，不重发业务效果。撤权/删除后旧卡片、总结、个人派生或经验不得重新注入。费用说明只关联确知的原调用与成果，未覆盖/未知显式保留，不说节省若干小时或ROI。

## 4. B：科研或课程项目验证同一机制

参与者提供实际要求、论文/实验记录和当前问题，界定数据划分、单位、设备/样本/协议等真条件。Agent可读原文、核对本项目记录，必要时使用已批准论文/文档/指标工具；论文元数据或他人结论不是本项目实证。

已有条件假设只在适用时进入上下文，缺失条件为UNKNOWN。真实新实验反例出现后应回同一claimId修订判断；没有新实验就报告当前未知，不替用户运行不存在的训练平台。持续责任可以是跟进用户上传的新材料或获准公开来源，不假设有任意磁盘监听或科研系统连接。

在PM已验收的组合，使用一条用户明确保存的协作偏好跨两个项目：科研优先核对数据条件，课程当次要求完整推导。检查它是否改变实际核查/必要澄清，而不是只换一句开场。CPU临时限制不提升为永久画像；源项目撤权后派生个人内容停用。

B的验收与A共用原引擎，换的是证据与条件，不新增“科研专用流程”。若两者都能完成同样原对象链、又能按不同材料选择不同工具/问题，才支持架构通用性。两种场景各一个项目只是早期案例，不是普遍效果或统计功效证明。

## 5. 应观察的智能行为与对照

| 判断机会 | 合理行为集合 | 失败反例 |
|---|---|---|
| 原材料已有答案 | 回读/引用或直接据有效上下文回答 | 反复要求用户重述；为显得智能强制联网 |
| 关键条件只有用户知道 | 问一项当前最重要决定，解释为何阻塞 | 猜测条件；一次塞进多个独立问题 |
| 假设受到新证据挑战 | 核对独立根、同一主张修订、重评下一步 | 多份摘要重复引用同源，仍当多源支持 |
| 合法工具暂不可用 | 原范围内替代/退避，说明覆盖损失 | 换Browser绕过撤销的Web grant、未准换模型/处理方 |
| 缺授权/成本/资料 | 明确停止、恢复条件、已做工作与未知 | 无理由死循环、用新任务清零预算、UNKNOWN后重发POST |
| 用户接管与恢复 | 回原身份、当前版本、保留原费用/结果 | 新建相似任务、旧批准复活、重复执行 |

实模对照至少包括：当前系统的正常运行；去掉适用记忆/假设或关闭Experience的配对条件。按原PM5协议逐步完成完整消融，决赛前不足以完成八条件时明确是先导，不删长期目标、不作全机制因果结论。模型/输入时间点/工具/权限/总预算相同，未来答案、用户后续纠正不回填过去。独立评分至少两名，分歧复核；模型打分只辅助。

## 6. 一份证据，各轨独立签收

沿原T-ENG/T-FIRST/T-MODEL/T-SIM/T-DEVICE/T-DAYS/T-OUTCOME七轨记录，Security/Functional/Evidence三类Gate不混算。每条证据包含caseId、project/原对象、源码/dirty/配置指纹、provider/模型、设备、同意范围、实际起止、结果和未完成覆盖。

| 指标 | 真实分母 / 读法 |
|---|---|
| 首次有依据价值 | 所有开始的合格用户，含退出/解析失败/零额度；材料到正确可用判断的时间和错误，不只统计成功者 |
| 重复解释/提问质量 | 应可复用背景/金标决策机会；必要遗漏、过度/重复提问分开，不能只报平均轮次 |
| 自主调查 | 证据支持、适用条件、合法改道、问题/停止质量及成本；不按工具顺序或数量给分 |
| 持续责任 | 计划/实际观察、无变化/失败/未检、恢复和累计用量；三真实日期与实际时长分报 |
| 鸿蒙减负 | 正常入口到原问题步数、错误和找回时间；手机短回应后Web读回同一对象；SDK/HAP不代替操作 |
| 记忆/经验收益 | 配对正确判断/负迁移/费用；采纳、完成记录、独立效果分别记录 |
| 用户信任 | 能解释依据、未知、模式和停止方式；满意度只是辅助，不能替行为 |

权限越界、隐私泄露、旧generation发布、预算越界或重复业务效果为硬失败。正确停止、无变化、无新Dream和保留UNKNOWN不是需要剪掉的“失败剧情”。

## 7. 三日之后与参赛素材

三日是冲刺内可做的早期真实观察，不代替PM5一周/月/三月。保留长期目标、退出与数据删除，并报告样本限制。

视频可以选取正常产品的真实历史记录，以时间戳和来源解释跨日；删减等待时间可标“跨日记录节选”，不能剪成连续即时执行。现场失败可以使用既有核实录像/产物说明，它们属于材料备用，不是产品离线推理或新增演示控制台。素材授权、包版本、是否历史/脚本/真实模型/设备必须对应，旧合成截图只用于工程说明。
