## 用户现在能做什么

- 同一浏览器换账号、换项目时，采集草稿不再按共享项目串用。退出、失去项目权限和跨标签页换账号会停止旧草稿消费；旧鉴权和保存响应不能恢复旧账号状态。无账号标识的旧草稿不自动分配给当前用户。鸿蒙快速记录、列表加载和卡片写入绑定会话及 generation；基础卡片缓存也需匹配当前账号与未到期会话，旧版无归属缓存回到待同步状态。
- 普通成员不再看到项目删除入口，直接调用 DELETE 也会被拒绝。所有者的确认绑定项目 ID 和已读版本；旧版本必须重新核对。
- 删除先停用项目，再由原 Worker 清理文件。文件失败时保留清单和回执，项目列表可查清理进度；成功后才报告完成。独立备份、外部副本不在本次应用内清除范围。
- 新版 Web、鸿蒙建项请求支持丢失回包后按原请求重试。项目、OWNER 和原 AgentRun 回执在同一事务提交。
- 新记录区分云模型整理、规则整理、云端失败后备及未记录方式；重放读取原 Capture 的处理回执。历史缺失字段保持未知。
- 云能力查询核对配置和当前账号额度，但不请求模型、不占用额度；界面不把“配置存在”当作服务连通。
- 后台状态区分心跳、成功巡检、领取记录、巡检失败，以及 Web/Worker 版本、数据库和配置不一致。
- 个人记忆在模型调用前绑定到原 Mission。没有 Step、或另有大量 CHAT Run 时，暂停、纠正、删除仍能使原依赖失效，保留预算与 UNKNOWN 预占。

## 关键技术边界

1. 项目销毁没有新建 Runner。清理身份使用 `provider=project-deletion-v1` 的原 AgentRun，`projectId=null` 使无正文回执在项目删除后可查询；只保留 owner、项目身份、文件清单和进度。每轮最多处理 5 个项目、每项目 50 个文件，文件删除幂等；文件故障保留原五分钟租约退避，给其他项目清理机会，到期由原 Worker 重试。正常的大批文件分段不加此故障退避。
2. 项目停用及成员资格移除在原事务提交。原 Continuity 消费者同步失效；SourcePolicy、派发预占和保存边界拒绝停用项目。与其他项目混合的会话不被粗暴整段删除。
3. POST /api/projects 支持 `Idempotency-Key` 或 body.requestId；二者不符返回 422。原请求绑定规范化输入，同 ID 改内容返回 409，原项目已不可用时不重建。
4. DELETE /api/projects/:id 需要 `X-Project-Delete-Confirmation: <项目ID>` 和 `If-Match: <项目updatedAt ISO>`。PENDING 返回 202，完成回读为 200；不能再将“收到请求”解释为文件已全部清除。认证 owner 可通过 `/api/project-deletions` 和 `/api/project-deletions/:id` 读取自己的进度。
5. 个人记忆依赖只进入原 Mission.planJson 与原审计回执；没有第二套记忆或任务状态。迟到模型响应不能绕过 lease/readSet 守卫，不退款或重置 UNKNOWN 预占。
6. Worker 的 RECENT 表示观察到近期心跳，不是所有来源健康。数据库标识只输出 hash；不公开数据库路径、凭据或个人正文。空闲队列检查、领取工作、模型判断和现实目标达成仍是不同事实。
7. 迁移只新增 `Project.deletionRequestedAt` 与 `Capture.processingJson`，不 seed、不 reset。旧 Capture 的空处理方式不会回填成实模或规则成功。
