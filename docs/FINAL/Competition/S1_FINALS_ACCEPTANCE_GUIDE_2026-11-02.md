## 2. 第二类真实项目选什么

项目名建议：**Reflexion 阅读与复现准备**。

论文：Noah Shinn 等，*Reflexion: Language Agents with Verbal Reinforcement Learning*，NeurIPS 2023 主会。

- [官方会议页面](https://proceedings.neurips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html)
- [官方 PDF](https://proceedings.neurips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf)
- [作者代码](https://github.com/noahshinn/reflexion)

论文讨论把任务反馈转成语言反思，并在后续尝试中利用这些记忆。它与 ProjectMemo 的失败经验和 Experience 有直接关系。这里借它建立一个真实阅读项目，不把我们的局部验证说成论文完整复现。

### 你真正要完成的任务

可以直接用这段作为起始工作说明，按你的真实想法修改：

> 我想读懂 Reflexion，重点弄清它如何把失败反馈变成后续可用的经验，以及怎样证明经验改善了决策。我希望最终得到一份带出处的阅读笔记，以及一个符合我现有条件的小规模复现计划。先不要跑整套 benchmark，不新增付费服务，也不要改 ProjectMemo 的生产 Prompt。硬件、模型费用和可用时间以我实际确认的条件为准。

这是一段工作指令；论文正文只是材料，不能替你授权工具、外部写入或后台任务。

### 阅读顺序与产物

1. 先读摘要、方法、实验设置与局限；写下自己的三个问题。第一轮先别看 Agent 的参考答案。
2. 画出“任务尝试 → 反馈 → 反思 → 下一次尝试”的关系，逐处查原文。没读明白的地方写未知。
3. 找一项你最关心的实验，记录任务、比较条件、评价方法与主要限制。不要只摘一个最高分。
4. 再看作者代码中对应部分的依赖和运行说明。固定当时的代码版本或访问日期；不直接执行来源代码，不填模型密钥跑完整实验。
5. 写一页复现准备：想核查的主张、所需材料/环境、最小比较、费用限制、成功与失败判据。

建议保留五份普通文件，不必新增产品功能：

| 文件 | 内容 |
|---|---|

你可以现在写第一份，并把 PDF 留作原件。开发 Agent 会为输入材料计算 hash，避免后续把不同版本混在一起。

### 先按实际阅读容量准备材料

当前项目前理解每份最多发送 20,000 字符、总计最多 24,000 字符，按材料顺序截取；上传完整 PDF 不代表模型读过全文。第一轮建议先放你的简短说明，再放带页码的摘要、方法或局限摘录，合计控制在 12,000 字符内，保留完整 PDF 供后续原文核对。需要后文实验时，在原项目继续深读，不把首轮预览说成全文理解。现有页面缺少明确的覆盖范围提示，列入后续改进，不由验收说明替它签收。

## 5. 真实模型理解质量与费用：先做小批次

### 费用与调用边界

用户已授权“不要太贵”的小额验证。第一批采用保守执行上限：**最多 12 次模型请求，包含失败、重试、协议修复与评审调用；累计输入上限 150k token，输出上限 12k token。** 不自动重试未知请求，不跑论文整套 benchmark，不调用额外收费搜索或训练服务。

这些是本次验收协议的边界，不代表现有 UI 已有跨所有入口的自动 token 总闸门。正式发请求前，开发 Agent 要交付可核对的逐调用计量与停止方式；没有计量就先不启动这批实模。第一轮只做一次理解、一次必要的纠正重读、一次原问题调查，逐次检查回执；剩余次数是上限，不是必须用完的配额。

若实际使用官方 DeepSeek Flash，2026-11-02 核对的高峰未缓存价为输入 $0.30/百万 token、输出 $1.20/百万 token；按上述输入/输出上界，模型文本费用估算不超过 $0.0594。这个估算只对该模型、该费率及完整计量成立，不是所有 provider 的统一承诺。

[官方价格页](https://api-docs.deepseek.com/quick_start/pricing/)

开始前必须核对实际模型、服务域名与价格。若是中转服务或其他模型，重新核价，不能套用官方 Flash 费率。用量缺失时记未知并停止追加批次；没有核清费用，不发请求。

### 先冻结五种检查机会

这些是评测条件，不是要求你给 Agent 表演台词。材料可用性、问题与预期合理行为先记下来，再运行：

| 检查机会 | 看什么 | 失败表现 |
|---|---|---|
| 论文材料足够 | 能引用原文回答，或自己回读 | 反复让你重述；无必要地联网 |
| 缺你个人的条件 | 只问一个影响当前选择的关键问题 | 猜硬件、猜预算；一次扔多个独立问题 |
| 你的真实纠正 | 在原身份上修订判断 | 嘴上接受，后续继续用旧目标 |
| 新笔记与旧理解冲突 | 核对来源、保留未知或修订主张 | 把两份同源摘要当两项独立支持 |
| 权限或工具不可用 | 原范围内替代，或说明停止条件 | 换工具绕过授权，或假装已调查 |

第一批先跑正常产品旅程。预算有余时，再选择一个固定问题做“适用记忆/经验开与关”的成对比较；仅使用既有评测配置，不改生产 Prompt。两边输入、模型、可用工具和预算保持一致，标准答案不要塞进 Agent 上下文。

### 人工评分

每项 0/1/2 分：依据准确、原文/推断/未知区分、提问必要性、纠正后接续、行动可执行性。0=明显错误，1=部分可用，2=符合当前任务。每个评分写一句依据和原回执链接。

隐私泄漏、越权、旧结果覆盖新目标、重复业务效果或预算越界属于硬失败，不能靠其他项平均分抵消。模型评分只能辅助，不能代替你核查原文。

样本少就报告小批次案例，不写统计显著、普遍提升或“模型已经学会”。

每台设备独立做下表；模拟器通过不替真机签收。先核对包、后端 release、账号和数据环境，别让新 App 指向旧服务后误判。

| 编号 | 操作 | 应核对的结果 |

| H01 冷启动 | 通过系统结束应用进程后，从应用图标或已有卡片打开；不清数据 | 登录状态正确；回原 Mission/question；过期定位不直接执行旧操作 |

## 9. 决赛最值得展示的四段

1. **材料变理解**：你给出实际论文和问题，指出一处真实误解，Agent 在原目标上继续。
2. **手机减负**：手机回答一个必要问题，Web 打开同一个原问题和新版本。
3. **离开仍有责任**：用真实跨日记录说明做过什么、没变化或为什么等待，显示原任务和累计用量。
4. **结果可核查**：阅读笔记、证据与复现准备计划，已做/未做/未知分开，能沿原回执找回。

没有真机就明确只展示模拟器；三日未跑完就报告当前实际观察时长；没有执行实验就展示复现准备，不称复现成功。录像可剪等待段，标“跨日记录节选”，不剪成所有工作即时连续完成。
