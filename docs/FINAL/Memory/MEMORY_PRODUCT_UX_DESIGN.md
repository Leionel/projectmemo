# 记忆怎样出现在日常协作中

日期：2026-11-01。以下是拟实施的双端交互。现有入口与缺口见 [源码审计](MEMORY_ARCHITECTURE_AND_SCOPE_AUDIT.md)，数据与失效规则以 [Agent 集成合同](MEMORY_AGENT_INTEGRATION.md) 为准。本次没有修改页面，也没有将线框当成已验收界面。

## 1. 先让用户完成事情

记忆不需要成为每天维护的第二份工作。日常只围绕三件事：继续当前项目、让忆程调查一个问题、查看需要自己回应的事项。个人记忆主要在设置中管理，在协作中按需露出。

这次不为 Memory、Dream、Experience 各加一个一级入口，不把系统状态全部铺成卡片，也不把空对话框长期占在内容旁边。列表、正文和主要操作先排好，再决定哪里需要容器。

Web 用列表和必要时打开的详情；鸿蒙用单列和详情页/底部弹层。共享条目身份、版本、权限和错误语义，信息密度可以不同。现有配色、字体和导航先保留，视觉调整须用同尺寸真实截图比较。

## 2. 设置 → 我的记忆

现有 Web `GlobalSettings` 主要管理模型配置，不能直接往其中塞一大段个人画像。建议在设置入口增加“我的记忆”，进入独立的账户页面，例如拟议 `/settings/memory`。鸿蒙从 Index 的 SettingsTab 进入独立页面，不把完整编辑器嵌进长设置列表。

### 默认页面

```text
我的记忆                                      添加

用于你自己的项目协作                         使用中

已记住                 待确认的理解 2

技术问题先给结论，再按需要展开                 >
适用：技术讨论

先用小规模验证排查问题，再扩大实验             >
适用：研究与开发建议

记忆使用与控制                               >
```

数量来自当前服务端视图，不预填数字。默认展示几条最相关的当前条目，提供正常分页；停用和过往版本放在筛选/详情中。首屏不显示 confidence 分数、token 用量、claimId 和完整来源链。

“已记住”和“待确认”可以切换，但不强制以卡片容器包住每一行。Web 没选条目时不预留巨大空详情区；点击后再打开侧面详情或进入页面。鸿蒙整行可点击，主要操作至少有 44vp 命中区，清除和返回均有可读名称。

### 条目详情

先显示完整陈述、适用范围和当前状态，再给“修改”“暂停使用”。来源、形成时间、版本经过和最近使用记录逐层展开。删除放在次级菜单，明确区分暂停与删除，不用一组同权重危险按钮挤在内容上方。

来源解释示例：

> 你在 11 月 1 日的技术讨论中明确提出。你选择了用于今后的技术讨论。

候选解释示例：

> 最近几次项目中，你都先检查基线再比较新方案。这可能只是当时的需要。要把它保存为通用协作偏好吗？

候选详情保留支持场景和例外，主要操作是“按这个范围记住”；也可修改文字、仅留在原项目、暂不处理或拒绝这类建议。一次确认只针对冻结的条目、范围与版本，不是永久同意未来所有推断。

### 三种保存入口

| 入口 | 用户动作 | 系统反馈 |
|---|---|---|
| 主动添加 | 在“我的记忆”填写内容与范围 | 原话明确时直接保存，显示实际生效范围和撤回入口 |
| 对话中明确交代 | “以后讲技术问题先给结论” | 范围明确且允许显式提取时直接保存；简短回执，不额外弹一次确认 |
| 模型归纳 | 从多个场景提出可能规律 | 进入待确认，未确认不影响调查和表达 |

“这次详细一点”只影响本次。“以后都按这个来”若指代不清，只问一句“仅这个项目，还是今后的技术讨论？”不能把模糊句子默认为永久偏好。

### 修改、撤回与删除

- 修改保留原文本草稿。若另一端已改，展示当前版本和本地草稿，让用户核对后提交，不能静默覆盖。
- 暂停使用保留内容。返回账户页仍可查看，模型上下文不再使用；账户暂停不能被某个项目的 ALLOW 覆盖。
- 撤回停止当前有效版本。旧输出保留历史标记，接续时按当前视图重核。
- 删除说明“已停止使用”和“内容清除进度”。已进入外部系统的内容不会因删除记忆自动被撤回；如需处理，进入原业务对象核对。
- 请求丢回包显示“结果待核对”，重读原 requestId 的回执；按钮不改成“重新保存一份”。

### 使用与控制

二级页面分清三件事：使用已保存记忆、从明确表达中保存、归纳候选理解。再提供项目例外、临时不使用、导出和删除。首批候选推断默认关闭；显式保存始终有可用入口。

首次开启使用时说明个人内容将在哪些已选模型/服务中处理，并服从本轮原有模型许可。允许保存不等于允许外发；若只允许本地规则处理，界面不能显示“已用于云模型”。这是一项可管理的处理选择，不是每次回答弹窗。

关闭使用后说明项目资料与原委托仍保留。不能把关闭个人记忆渲染成“Agent 已不能继续工作”。重新开启也不能把已删除内容从旧聊天自动重建回来。

## 3. 项目 → 记忆

逻辑入口是“这个项目目前知道什么”。实现继续复用 Web `/projects/:id/knowledge` 的 AgentMemoryPanel/KnowledgeFeed，以及鸿蒙 MemoryTimeline。当前“资料”用于采集原始内容，不同时塞进完整个人档案；命名调整应结合整条项目导航验收。

页面默认先给当前理解和仍需核实的问题，再按需看变化与原资料。

```text
项目记忆                                    搜索

当前理解
本轮先核对数据划分，旧指标暂不能直接比较。
依据已变化，今天需要重新核对。
查看依据              纠正这段理解

待核实
增强策略可能在小样本上更稳定。               查看条件

原始资料 / 变化经过 / 原任务与结果             >
```

这段示例是假想数据，不能作为预置的当前结论。实际读取失败时显示失败，不用上一次综合填充为“当前理解”；有历史可保留标时内容，写操作继续受服务端保护。

“待核实”里保留原问题、支持和反例、未知条件、下一条信息需求及回原调查入口。SUPPORTED 显示“在这些条件下有支持”，不能省成“已证实”。解释纠正与“以后不要用这份资料”是两个操作，后者走原 SourcePolicy。

项目记忆页提供小型“本项目如何使用我的记忆”入口。默认遵从账户策略；用户可选本项目只用项目资料。项目负责人不能查看其他成员的个人条目。成员切换账号时，页面和草稿按原账号命名空间隔离并清除当前展示。

## 4. 首页和 Agent 对话

个人记忆的价值应在任务里看见，不靠每次展示一排“已引用记忆”徽标证明。

### 何时提示使用了记忆

| 场景 | 建议呈现 |
|---|---|
| 只沿用“先给结论”的表达习惯 | 不必每条消息重复声明；详情可查 |
| 背景改变了调查或建议 | 在原因中说明“沿用你确认的先做小规模验证，我先核对了这两项条件”并给展开入口 |
| 当前请求覆盖旧偏好 | 自然说明“这次按你的要求展开推导”，不要求先去修改永久条目 |
| 旧背景已到期或矛盾 | 只问受影响的问题，例如“当前还能使用原来的设备吗？” |
| 来源撤权 | 显示“原背景暂不可用”，不泄露原项目名称、片段或私人细节 |
| 联想到另一项目的方法 | 先提出关联与可读范围；需要原文时请求选择资料，不能直接引用未授权项目内容 |

“为什么这样建议”沿用当前 AgentExperience/生成式 UI 的解释入口。展开后区分当前指令、项目证据、个人偏好和方法经验；这些是可点开的来源，不是四块必须常驻的大面板。

使用记录用准确的阶段名称：“本次带入了上下文”“回答关联了这条背景”“已收到反馈”。没有对照结果时不显示“这条记忆让你节省了十分钟”，也不把模型自述当成因果解释。

### 就地纠正

用户可在依据旁选择“这次不适用”“修改这条记忆”“不再使用”。默认的“这次不适用”不能永久删条目；永久修改也不能仅改一段显示文本。服务端回执确认后，更新原消息的使用状态，保留当时版本。

Web 用已有弹层/抽屉承载短编辑；鸿蒙用底部弹层或详情页。长文本不能强塞在小弹层里，键盘弹起后输入和主操作要可滚动触达。返回、旋转、进后台和超时后草稿保留，提交仍绑定原条目版本。

### 生成式 UI 的边界

可增加三种有限展示块：个人记忆使用说明、候选确认、版本冲突读回。块数据由服务端绑定当前 owner、条目版本、内容 hash 和允许动作；模型只选择已有模板，不生成任意写入 URL 或按钮权限。

候选确认与原 Mission 批准不能合在一个“好的”按钮上。一个入口确认理解，另一个入口批准冻结的业务提案；读过、通知到、确认记忆、批准行动、执行成功分别有自己的状态。

## 5. 首次使用、一周和一个月

首次使用仍从项目和真实问题开始。用户可以跳过个人记忆，不填“个人画像问卷”。在第一次明确表达偏好后，轻量说明已经保存的内容和范围；没有明确表达便不为了填充空页面制造记忆。

使用一周后，可以在原对话或设置中看到少量有来源的候选。多条候选合并展示，拒绝后不反复催确认。同一背景已可用时少问一次；背景不够确定时照常澄清。

使用一个月后，用户可查看近期哪些任务使用过重要记忆、曾怎样纠正、哪些内容已停用。长期关注可以帮助提出下一次研究问题，但建议仍回到具体项目，不能把整个人生方向变成默认自动委托。

三个月场景需在 PM-5 做真实跟踪；这些描述是目标体验，不是已完成的研究。

## 6. 跨端能力边界

| 端 | 首批范围 | 不预设的能力 |
|---|---|---|
| Web | 完整查看、添加、候选比较、来源、使用记录、项目例外、纠正和导出 | 没有真实授权不能替用户批准外部效果 |
| 鸿蒙手机 | 查看、添加短条目、候选确认、纠正/暂停、项目例外、原任务接续 | 不依赖页面常驻来保证后台任务执行 |
| 小艺 | 继续原认证和项目绑定流程；可读当前任务摘要并跳转 | 首批不通过含糊语音永久新增个人记忆或批准删除 |
| 桌面卡片 | 沿原脱敏规则显示任务和变化，跳转原页面 | 不直接放个人背景、候选画像和私有原文 |
| 穿戴设备 | 留接口兼容和简明状态语义 | 未验证平台权限与设备前不列入已交付能力 |

设备断线时可显示本地历史，并明确标记；不能离线确认永久记忆的当前版本。账户退出清理明文视图，安全草稿按现有账号存储边界处理。服务端先判权限，双端共用回执与失效版本。

## 7. UI 验收要看真实画面和操作

1. 新用户、已有条目、只有候选、全部停用、搜索无结果、权限失效、读取失败分别有正确状态；不把“未选择条目”显示为“没有记忆”。
2. Web 宽屏和窄屏使用相同数据；无空详情区长期占位、悬浮入口遮表单、双重下拉指示或长标题撑破布局。
3. 鸿蒙验证键盘、返回、后台恢复、大字号和错误读回；页面构建通过不算这些场景通过。
4. 修改与删除经确认回执后两端同步；另一端旧草稿不能覆盖新版本。等待中不清空内容，也不提前显示已生效。
5. 请独立观察用户能否找到依据、纠正和项目例外，不先教他们理解 Claim、Digest、Dream 等技术概念。
6. 截图保存到新目录，标明数据为合成还是用户测试数据、模型是否真实。先比较相同尺寸的前后画面，再决定是否合并视觉变更。
