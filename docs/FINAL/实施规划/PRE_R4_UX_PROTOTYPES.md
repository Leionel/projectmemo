# Pre-R4 双端关键页面原型说明

日期：2026-10-22。设计规格，不是运行截图。关联[总体方案](ProjectMemo_双端功能曝光与UI优化方案_2026-10-21.md)与[R4 衔接契约](R4_UX_INTEGRATION_CONTRACT.md)。下文示例任务用于说明布局，不作为生产记录或已发生事件。可立即承载的内容只取当前服务数据；标注“R4”的区域只存在于设计稿。

## 1. 共同任务、范围和导航

用户打开一个项目，希望回答“目前如何、为什么变了、需要我做什么”，然后继续原任务。导航只改变所在页面；补料、批准、采纳调用原服务并读回持久结果。优先规则：`rule/one-primary-action`、`rule/preserve-mental-model`、`rule/name-object-scope-consequence`。

项目内五组为概览、委托、资料、行动、成果。桌面侧栏、窄屏 Web 紧凑项目导航、鸿蒙项目底栏共享名字和选中语义；全局项目列表/记忆/我的待办属于更高范围，不能在项目页悄悄替换其含义。返回列表写“全部项目”，项目头始终有可展开的完整名称。

| 组 | 主目的地 | 既有入口继续可达 |
|---|---|---|
| 概览 | `/projects/:id` | `/health` 作为“更多项目状态”，保留原体检、状态、Episode、准备度锚点 |
| 委托 | `/missions?mission=:id` | 创建、历史、草稿、审批和执行详情；无 OWNER 权限不泄漏私有数量 |
| 资料 | `/records` | `/knowledge` 的记忆/问答/归档整理；`/meetings` 会议；附件、卡片实体锚点 |
| 行动 | `/actions` | 行动板、提醒、排程及结果复盘的原锚点 |
| 成果 | `/generate` | 文档类型、版本、阅读/审阅、来源定位 |

完整目录在“项目功能”展开中列出原八个目的地。资料进入后有“记录与附件 / 项目记忆 / 会议”二级入口，不能把知识与问答藏到无法发现的位置。问忆程为固定文本/图标轻入口；记录进展为快速动作，二者不再占一张首页大卡。当前页、筛选、实体与返回地址保持可恢复。`rule/navigation-vs-action`、`rule/smallest-intervention`。

## 2. 视觉候选与推荐 Token

### 2.1 同内容比较

两套候选使用相同布局、字级、问题和按钮，避免用不同内容诱导选择。下框中的背景/强调是颜色角色，不是完成状态。

```text
A 暖纸青墨                            B 冷白墨蓝
暖纸底 #F7F6F2                        冷白底 #F4F6F9
项目：阶段汇报                         项目：阶段汇报
--------------------------------     --------------------------------
等待你补充                            等待你补充
还缺同条件下的对照组指标                还缺同条件下的对照组指标
已保存草稿，检索记录可查看               已保存草稿，检索记录可查看
[补充实验结果] #27685D                  [补充实验结果] #3D5E86
查看原委托 · 查看依据                   查看原委托 · 查看依据
```

推荐 **A 暖纸青墨**，延续已有 Web 的记忆/资料气质，收掉营销式透明材质和全标题衬线；鸿蒙从饱和蓝转向克制青墨。B 保留为对照方案，不混成第二套按钮语言。推荐是 H4 设计判断，需 UX-0 实际内容/主题走查验证，不宣称用户偏好结论。

### 2.2 推荐语义角色

| Token 角色 | 浅色 A | 深色 A | 用途 |
|---|---|---|---|
| canvas / surface / raised | `#F7F6F2` / `#FFFFFF` / `#FFFFFF` | `#151E1C` / `#1D2926` / `#263630` | 页底/内容/浮层；层级同时靠间距和边框 |
| ink / secondary | `#1C2E2C` / `#53645E` | `#E8EEE9` / `#B3C4BB` | 正文、解释；次要文字仍需可读 |
| accent / onAccent | `#27685D` / `#FFFFFF` | `#91C6B5` / `#151E1C` | 当前主操作和选中，不表示“成功” |
| accentHover / accentPressed | `#215A51` / `#1B4C44` | `#A8D2C4` / `#7AB39F` | Web精确指针和按下；不改变业务状态 |
| selectedSurface | `#E7F0EB` | `#263F35` | 当前目的地浅底，配选中标记/文字 |
| border / controlBorder | `#D9E1DB` / `#718278` | `#3B4D44` / `#859B8D` | 装饰分隔 / 需要辨认的输入边界，不能混用 |
| focus | `#27685D` | `#91C6B5` | 可见焦点环，加间隔避免与选中底融合 |
| danger | `#A9343C` | `#FFB4B8` | 执行失败/破坏性操作，配明确动词 |
| warning | `#8A5700` | `#F2C77D` | 等待核验/过期提示，不把全部未知当风险 |
| info | `#355F84` | `#A9C9EE` | 已受理/普通信息，不能与成功共用勾选 |
| success | `#236447` | `#A3D4B1` | 明确持久操作成功，文案写具体对象 |

颜色核算按 sRGB 相对亮度比进行，结果写入文档核对回执。普通正文目标至少 4.5:1；必要控件边界/焦点目标至少 3:1（项目验收门槛）。装饰分隔不作为唯一边界；禁用仍有原因文字。计算不涵盖抗锯齿、透明混合、设备显示和读屏，需渲染验收。

Web 系统无衬线正文16、次要14、元信息12、区域18、页标题24；鸿蒙保留系统字体与既有15正文/18区域/20页标题角色。间距4/8/12/16/24/32，手机16页边、桌面24–32。默认容器圆角12–16，按钮沿平台形态；不把所有内容套胶囊或玻璃卡。字号是 H4 角色提案，不是 ArkUI 官方强制值。

头部只交代范围，说明文字可展开。焦点占主区域宽度，普通内容用两列和分隔；没有草稿或变化则不保留空大卡。只读聚合不可等待模型、附件提取、持久评估或完整事件查询。部分聚合失败局部显示重试，资料和行动入口仍能用。

紧凑导航建议保留在文档流顶部，不叠加第二条八项网格。快速动作可采用安全区内轻工具栏；键盘打开时让位于输入，不覆盖表单提交/焦点。普通字号下首屏至少看到范围、焦点和主动作；大字体允许自然增高，不能为了固定首屏切掉问题或按钮。标题可短显，但点击展开完整名称，不要求 hover 才可读。

项目范围始终明确；返回全局后才恢复全局导航。既有问忆程移为稳定轻入口，不能因底栏改组消失。捕获、选择材料、审批优先原生表单/页面；长来源和复杂审阅使用独立详情，不叠多个弹窗。平板可采用导航栏+内容/详情分栏，不能按比例放大手机；本轮手机和 Web 为必验，其他设备先冻结适配策略。

### 首焦点与多任务

按“需要我回应 → 真实临期/高影响阻断 → 可靠变化 → 正在推进 → 起步”选择，结合用户截止/优先级；同级稳定排序。未知严重性不冒充紧急。多项需回应仍显示数量和队列，主焦点不能隐藏第二个即将到期批准。用户正在阅读/输入时只提示新事项，不自动滚动或更换焦点。

主卡、变化、当前委托按实体去重：同一等待问题在主卡呈现后，委托区只显示简行及状态，不再复制整段。所谓进度是“最近保存了什么”，不是随意百分比或完成步骤数/当前计划数估算总进度。`rule/structure-before-containers`、`rule/cover-reachable-states`。

## 4. Mission 详情：活动摘要和按需轨迹

### P4：同任务详情

```text
‹ 返回委托列表      准备阶段汇报                   ⋯
等待你补充 · 原委托ID可复制（诊断层）
目标：依据已选资料形成带来源的阶段汇报       展开完整目标

当前需要：同条件对照组指标
为什么需要：当前材料只有实验组，不能完成对比结论
[补充指标/选入材料]      不知道/稍后（有对应服务才启用）

最近进展
✓ 已读取项目记录                  真实事件时间
✓ 草稿修订2已保存                 查看草稿
等待状态：以上进度保留，补充后重新判断是否可继续

草稿与结果   来源与依据   执行详情（按需展开）
草稿修订2：项目观察 | 外部参考 | 推断建议
Claim：未检查 / 待核验 / 有来源支持（按真实检查结果）
[审阅并归入项目成果]（条件满足时）

约束与权限 ▾  当前时间/费用/禁止方案/研究范围/接续授权
```

桌面可在左侧放委托列表和筛选，详情居中，来源就近侧栏；手机先列表再详情，返回保留筛选/滚动和未提交输入。创建委托作为列表独立动作，不在所有详情顶部占据长表单。多 Mission 用待回应/进行中/历史分组和服务分页，不将首页3条误写成全部。

摘要从 Step结果、Event、Output、Approval、Receipt确定性归纳，最多2–3项：动作 + 对象 + 真实结果 + 时间/定位。未取到时间不补造；重复租约/CLAIMED、心跳不出现在主要活动。工具参数、provider/cost、完整错误放执行详情；关键失败和恢复动作不能藏进去。不展示隐藏思维链、“正在认真思考”式流水文字或伪 token 实时流。

轨迹显示：时间、步骤状态、工具中文名、输入范围、结果摘要、来源/输出/回执定位。旧计划的OBSOLETE标“依据已变化，未执行”，SUCCEEDED仍为历史已执行。没有完整总步骤承诺时，不显示“完成3/5即60%”；可以写“3个步骤已执行”。

## 5. 可信控制：审批、补料、暂停与成果

### 5.1 行动提案审阅

```text
审阅：新增一次对照实验
将创建：本项目1项待办（不表示实验已完成）
标题 / 描述 / 优先级 / 截止（未设置就明确写）
依据：卡片C、附件修订R2（可就近展开）
批准有效期：服务端真实expiresAt
既有约束：不采用方案X / 当前费用上限（有才显示）
[批准创建行动]        拒绝提案        返回委托
```

批准只表示提案获准，实际写入须等执行回执；无回执时显示“批准已记录，等待执行”，不能显示“行动已创建”。超时保留同requestId并读回，不能立刻生成新批准。来源/版本变化409时保留原内容和用户输入，展示“依据已变化，重新预览”，不自动按旧点击批准新内容。`rule/name-object-scope-consequence`、`rule/preserve-user-input`。

### 5.2 材料接续的分层反馈

```text
已接收材料 → 提取/处理 → 找到相关候选 → 核对缺口 → 接续预览
             失败可重试   不等于充分     不足列具体字段
                                    ↓
                         [选入材料并继续原委托]
                         已受理 → READY/RUNNING → 新结果
```

沿用现有Continuation预览与确认。自动模式仅在已有结构化缺口检查、用户预授权和服务开关均允许时成立；普通文本输入转READY表示可以再评估，不代表充分性已通过。材料不足保留候选与原问题，不创建第二份Mission。公开研究授权与LLM上下文授权分别展示；不把公开主题许可解释成可外传私有实验。

### 5.3 暂停/取消/失败

RUNNING时点击暂停/取消，先显示“暂停请求已受理/取消请求已受理”，等服务端状态再切换。跨端恢复需要读取持久request flag的最小DTO扩展；未扩展前只呈现当前请求回执，不凭客户端记忆声称长期状态。PAUSED显示用户暂停/服务错误/预算等真实原因及允许的恢复入口。FAILED不使用只支持PAUSED的resume；先展示故障与现有可行路径。

### 5.4 草稿到项目资产

```text
草稿修订2 → 查看正文/块级来源/Claim核验
        → 采纳预览：将新增哪个成果版本、保留哪些来源
        → [归入项目成果] → 持久成果与MissionArtifactReceipt
        → 后续Mission检索 / 来源变更时定位受影响块
```

“已归入成果”只证明采纳行为。外部参考仍是外部参考、推断仍是推断；不把全部Claim升级为事实。来源不充分时就近标记，旧成果版本和完成回执保留。只有现有来源映射精度允许时显示具体块，缺映射写“可能涉及本成果，范围未定位”，不武断判整篇无效。

## 6. 项目演进与再进入

```text
当前状态                         评估于：真实时间 / 新鲜度
当前有支持的结论 → 来源/有效期/说明
有争议 / 证据不足 → 原因与可采取动作

最近重要变化
相较：快照X（时间、规则版本） → 快照Y（时间、规则版本）
旧描述 → 新描述       查看记录及确认关系
直接影响：已有映射的行动/成果/步骤
多跳影响：仅R4契约和服务具备后出现

关键历程
时间  发布的Episode修订/已确认关系/行动结果记录
      查看当时保存的内容（不宣称完整任意时间状态）
```

没有基线显示“尚无可比较快照，可查看当前资料”；首个快照只说明建立观察。跨schema/policy不能直接比较，提示重建可比基线。时间线按事件含义区分记录时间、观察时间、确认/生效时间；不把上传时间当实验发生时间。回看冻结快照标“截至当时”，当前核验结果另列。

原Snapshot时间跨界与覆盖缺口尚未修复时，明示观察时间/局限，不能仅因页面刷新宣称当前有效。用户离开多久不从updatedAt推测。没有访问基线不用“自上次查看以来”，没有来源/基线不能编造影响数量。

## 7. R4 原型：只保留交互规格

### 7.1 影响与方案比较

```text
概览变化 → 影响详情（默认分层列表，图为可选）
根记录 → 规则/关系 → 行动/成果块/Mission未执行步骤
每条：影响类型 + 依据/反例 + 覆盖/截断 + 下一步
                          [比较应对方案]（需R4可用）

方案审阅：问题 + 同一约束 + 基线/版本/有效期
原计划参照          候选A                候选B
实际delta           实际delta            实际delta
确定性指标          可行性/未安排原因      同口径指标
模型权衡            依赖/未知             依赖/未知
选择后查看：将新增/修改/取消的具体对象和日历待处理项
[采用所选方案]       保留原计划       修改约束并重新比较
```

原计划参照不计入“两种实质候选”。手机逐卡摘要+详情，保持同口径字段及清晰当前选择。缺工期不能显示精确完工时刻；SEARCH_EXHAUSTED写“本次未找到可行安排”，不写无解。陈旧后保留选择但要求新修订，旧点击不能静默采用新方案。

### 7.2 主动事项、外部候选与经验

主动问题放当前任务：“缺哪项信息 → 为什么影响此决策 → 回答/不知道/稍后/停止主题”；R4未实现的响应命令不得做成无效按钮。外部候选在资料页：“GitHub对象/版本/观察时间 → 候选关联 → 人工确认”，不自动完成行动。经验在建议旁就近展开：“来自哪些轨迹、何种条件、验证范围、反例、当前版本”，激活/暂停入口等待服务。任何一项都不新增一级导航。

## 8. 状态覆盖与可验证任务

| 状态/测试输入 | 必须看到/能做什么 | 不得出现 |
|---|---|---|
| 空项目 | 一个“记录第一条进展”动作；附件/会议可选；跳过引导 | 六张空大卡、虚构健康/完成度 |
| 有资料无Mission | 真实资料摘要；可编辑首目标建议、用户明确创建 | 自动付费启动、默认云模型外传 |
| 20+Mission | 分类、分页、明确可见数量范围、同ID直达 | 首页3条当全部、每条完整长指令 |
| 长标题/长URL/大字 | 正文自然换行、完整内容可展开、操作可达 | hover唯一全文、按钮被挤出、横向页面滚动 |
| 等待输入 | 具体问题、字段/单位/条件、选料/输入、原任务ID | 新料=充分、充分=完成 |
| 待批准/批准未消费 | 提案内容/后果/到期、批准与执行分别记录 | 一个绿色“成功”包办 |
| 排队/运行/暂停请求 | 服务真实状态、最近回执、可用暂停/取消 | 模型思考流、伪百分比、请求=已停 |
| 模型/网络失败 | 已保留进度、具体恢复、输入不丢、原任务可回 | 全部失败都写配置错误、无限spinner |
| 来源变化/过期/409 | 旧预览保留、差异和重新预览入口、历史可看 | 旧点击自动应用新提案 |
| 能力关闭/探测失败/401 | 关闭说明 / 重试 / 登录分别处理；隐藏私有信息 | 三者都静默消失或伪空列表 |
| 部分聚合失败 | 可用区继续读；局部错误/时间标签 | 整页封锁或把缺失当零 |
| 无时间基线/旧快照 | 当前信息或明确X→Y，标观察时间/局限 | 虚构上次访问和任意历史 |
| 成果采纳/行动完成 | 对应成果版本/receipt 或resultCardId | 采纳=Claim全真、创建=现实完成 |
| R4未启用 | 现有功能完整可用；设计稿单独标未来 | 生产空壳Lab/图谱/经验计数 |

任务走查：①不滚动长页找到待补料Mission；②读出暂停原因并走合法恢复；③批准后识别尚未执行；④新料不足时继续原问题；⑤查看一次有基线的变化及来源；⑥从旧卡片/附件/行动/审批链接精确定位；⑦Web发起、鸿蒙补料、Web审阅同输出修订。记录首次正确点击、误入口、滚动、帮助、耗时与错误解释，效果目标待基线测量冻结。

## 9. 控件、反馈与验收

| 交互 | Web | HarmonyOS | 验收 |
|---|---|---|---|
| 默认/选中/禁用 | 文字+图标，选中aria-current；禁用旁说明原因 | 系统语义/选中态，原生按钮和表单 | 颜色关闭仍能辨别；按钮名称明确 |
| Hover/Press/Focus | 仅hover:hover且pointer:fine启用hover；即时按下；focus-visible统一环 | 沿用系统按压/焦点，触摸不依赖hover | 键盘/触摸均完成主流程 |
| 加载/提交 | 稳定动作标签+busy，状态另写；慢请求可重试/读回 | 提交回执、轮询与前后台生命周期 | 页面不跳动，不重复业务写 |
| 折叠/状态更新 | 局部opacity/transform，建议150–200ms；不transition:all | 优先已有系统transition，保留exit IDENTITY取舍 | 可打断、返回位置连续、不锁输入 |
| Reduced Motion | 去除位移/装饰，仍保留即时状态反馈 | 使用目标系统可用设置/能力，无法读取时采用保守低运动 | 实机/浏览器设置后核验，不只看CSS存在 |
| 错误/权限 | 就近错误、输入保留、焦点指向可修复处 | 原生反馈/页面恢复，避免嵌套弹窗 | 错误可听懂，关闭浮层回触发点 |

四屏验收覆盖1280×800、390×844、320宽、默认及大字体，浅/深主题；手机有键盘、安全区、前后台和断网。Web键盘完整流程、可访问名称/焦点/读屏状态播报，鸿蒙无障碍顺序与系统表单另验。只测真实设备长帧后才判断性能，构建和静态原型不算触摸/设备通过。新增能力未到位时隐藏相应生产入口，已有数据与旧路由继续可达。

## 10. 规格验收结论
