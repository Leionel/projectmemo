## 与审查报告的差异

用户在实施中要求官网“加点酷炫的动效和卡片特效”，因此官网不再按报告的克制路线，新增了 3D 倾斜、光斑描边、纸卡层叠、滚动揭示和扫光。粒子、蓝紫光和滚动劫持仍未使用，工作台和鸿蒙仍按报告执行。

**长委托早期进展摘要（用户要求）**
- 挤出上下文的步骤和较早的用户回答，滚动压成不超过 2400 字符的线索（`lib/mission/earlierProgress.ts`），进入上下文的 `earlierProgress`。
- 确定性生成：不调用模型、不计额度、不写库、无迁移，原步骤保留。
- 只带工具、状态、模型当时的一句话、来源名和失败原因，不带结果正文，也不进 `sourceIndex`，不能作为引用依据。
- 与完整步骤用同一套来源许可，受限步骤只留序号和工具；启用来源抑制时不带早期回答。

## 实测（隔离库、mock 模型）

| 指标 | 实施前 | 实施后 |
|---|---|---|
| 手机对话消息区占屏 | 41% | 62% |
| 项目子页第一条行动的位置 | y=642 | y=513 |
| 手机上第一条行动 | 首屏外 | y=788，在 844 视口内 |
| 官网标题实际字体 | 含回退字 | 只用 `PM Editorial` |
| 官网滚动样式重算（减少动效，CPU×4） | 每帧近 1 次 | 全程 1 次 |
| 官网滚动主线程耗时（有动效，CPU×4） | 5.4 ms/帧（不限帧率） | 10.6 ms/帧（约 60fps） |

两次滚动的帧率条件不同，最后一行不能直接比较。它是一次扫完全页、所有揭示动画都在播放时的数字，揭示只播一次。

## 未完成与限制

- **HDS 悬浮页签（P2）没有做。** `HdsTabs` 要接管页面内容，而 `Index.ets` 用条件分支切页，要先重构，且需要在真机比较帧数据。
- **Web 共享元素转场没有做。** Next 文档仍标 `experimental`，稳定版 React 未导出 `ViewTransition`；只做了路由淡入。
- 鸿蒙 `AgentRunThread` 和琥珀批准卡只过了构建和单测，没有运行态验证：打开对话可能在生产写入。
- 鸿蒙共享元素、“减少动效”开关的实际效果未单独验证。`pm.reduceMotion` 目前只影响接续线和共享元素，不影响其他转场。
- 没有真机帧数据；官网 3D 和光斑只在有鼠标的设备上启用，低端设备表现未测。
- Web 字号、圆角 token 没有全量收敛（W16）；记忆页“应用筛选”的规则不一致未改（W13）。
- 遗留：`/actions` 的提醒文案里仍有 `experiment_log、code_issue` 内部枚举，来自服务端规则文本，未改。
