# uireference 视觉评估与鸿蒙 UI 改造 Prompt

日期：2026-09-15。已逐张查看 `../../uireference/` 的 14 张 PNG；同时核对当前 Index、ProjectHome、PMAppBar 及组件路径。未运行本轮真机 UI 验收，未修改业务代码。

## 判断

**作为设计方向有条件通过，适合改造；不能直接作为完整交互规范或已实现功能清单。** 蓝白底色、清晰标题、时间线、证据列表和重点行动适合 ProjectMemo。应保留“记忆、变化、依据、行动”的产品特征，不套用所有页面都带大宣传头图、环形分数及重渐变的通用仪表盘风格。

上下文：以鸿蒙手机竖屏、触摸输入为主要目标；参考为 AI 生成静态图；具体 SDK 和设备尺寸实施时读取工程。图中的状态栏、手机外框和底部系统横条不是应用内控件。以下均为 H4 项目建议，不声称为华为官方视觉要求。

## 可直接复制的执行 Prompt

```text
请在 D:\Projects\hongmen 基于 ../../uireference/ 的 14 张参考图改造鸿蒙端 UI，完成真实可运行界面及必要验证，不仅输出设计方案。

遵循 AGENTS.md。先阅读 UI_REFERENCE_REVIEW_AND_PROMPT_2026-09-15.md 的参考映射及问题边界，查看对应原图，再按当前源码定位相关页面。现有第一、二阶段的实现和用户未提交修改全部保留。

目标：采用参考图的蓝白视觉、清晰层级、时间线和证据导向，把“项目变化—依据—下一步行动”表达清楚。参考图提供视觉方向，不提供真实数据或额外功能授权。不要像素照搬整张长图，不把截图作为页面背景。

1. 固定导航与功能边界

- 保留全局“项目 / 记忆 / 待办 / 设置”四项导航。项目页保留现有“工作台 / 记忆 / 待办 / 问忆程 / 成果”的可达性；先核对当前实现，已有后续调整以真实导航为准。
- 风险中心映射到待办的主动提醒；不要为追图新增一级风险 Tab，也不要删掉成果或问答入口。
- 全局列表明确所属项目，项目页展示当前项目，返回及深链不串项目。全局新增记录时明确选择项目；项目内新增继承当前项目。
- 不新增会员、多用户头像、导师发送、语音录制、自动后台推送、自动排程或小艺连接等未实现能力。发现真实已有能力可复用，没有则省略，不做假按钮。
- UI 改造不修改幂等、确认、状态判定、来源修订和权限逻辑。必要 API 展示字段可以适配，但不能为了外观写入虚构业务数据。

2. 统一视觉基础

复用 common/DesignTokens.ets、components/PMAppBar.ets 和 PMIcons.ets。先检查现有 token，再集中调整颜色、字号、间距、圆角及控件状态，避免各页散落常量。

视觉建议（项目风格起点，不是官方规范）：
- 浅灰蓝页面底色、白色主体卡、深蓝灰正文、清晰蓝色主操作；青绿用于完成，橙用于警示，红用于危险/错误，灰用于未知或禁用。
- 暖红底只强调当前高风险，不把全部提醒都涂红；“当前有效”不因内容涉及风险就使用错误态颜色。
- 页边距约16–20vp，卡间距12–16vp，主体卡圆角约16–20vp；正文约15–16fp，次级13–14fp，标题约22–26fp。根据现有字号体系和大字体实测调整。
- 主操作触摸区建议至少48vp；图标按钮有语义名称。状态用文字和图标共同表达，不只用颜色。
- 山形浅色背景最多用于顶部装饰，保持正文底色稳定；避免大面积模糊、重阴影、多层嵌套和每页重复英文口号。
- 不绘制系统状态栏、手机边框或系统手势条。保留忆程品牌名称和实际应用图标。
- 保持系统字号和主题能力；浅色图不能成为破坏现有深色模式的理由。

3. 分页改造

工作台：参考首页图。项目名与更新时间清晰；指标只显示实际截止、准备度、风险、行动。四列在窄屏改2×2或精简行。首屏突出最重要提醒和一个下一步；活动记录、缺口、更多证据在下方。新建项目和记录入口继续可达。首次/无变化/过期/错误分别显示。

记忆：参考时间线图。按日期分组，条目展示标题、简短摘要、类型、顶层生命周期状态、来源与项目归属。类型筛选和有效性筛选分开，保留已归档入口和恢复。长列表使用工程可用的高效列表组件。不要把行动实体和知识卡片类型混为一谈。

待办与提醒详情：参考风险中心、风险详情和行动看板。保留提醒/行动切换。提醒突出原因、时效、来源数量和处理入口；详情展示why-now与实际证据。接受、延期、忽略保留现有语义。行动显示任务状态、依赖判定、真实估时和截止；列表简洁，详情再展开。完成仍需走结果回执流程，不改成无输入直接DONE。

状态与简报：参考状态变化、整体状态、简报图。展示真实前后快照、变化、影响和建议，每项可打开来源版本。“健康度72%”“可信度85%”“较上周+12%”只有存在明确计算口径与有效数据才能展示；否则用后端状态或已确认数量，不用准备度冒充健康度。无历史数据不画趋势线。阅读和“已了解”的游标语义不变。

交付缺口：参考交付清单图。完成项、缺失证据和补齐入口来自实际交付物。数据不支持进度百分比时显示状态/数量，不为每个条目填模拟进度。截止日期按项目事实计算，不复制参考图的8月日期、9月日期或剩余天数。

会议：参考会议前后对比。输入、候选预览、确认中、已应用是不同状态。窄屏逐项上下展示旧值/新值，宽屏再用两列。原文片段、待澄清字段、勾选项清晰；确认冲突保留输入并重新预览。没有成员模型不显示虚构参会人。已应用后展示执行回执，不能仍用相同按钮重复创建行动。

快速记录：参考录入图的项目归属、输入区、附件与主要操作。优先保证键盘下可滚动和保存按钮可达。现有后端若只有“保存时结构化”，就使用保存后结果页，不调用有写入副作用的API伪装预览。不要在每次输入时发模型请求。暂存只有真实可恢复草稿机制才展示；取消不得默默丢弃未保存文本。保留requestId与重试语义。

证据页：参考证据依据图，展示结论、判定、原文、来源版本、时间及冲突。来源类型不同不直接标“独立互证”；没有结果记录应表述“尚未记录完成证据”，不能自动断言现实未完成。不要增加未经校准的可信度分数。

设置与问忆程：设置采用分组结构，展示真实模型模式、后端连接、提醒策略和已有功能入口。“已连接/已同步”由实际状态驱动。应用内问忆程继续保留自己的身份，小艺图片仅用于证据卡布局参考，不复刻系统小艺外壳或冒充已接入。

4. 实施顺序与适配

先完成token和工作台的纵向改造，运行查看实际效果后调整；再扩展记忆、提醒/行动、详情/表单与设置。共享样式稳定后复用，不要求先重写整套组件库。

至少验证窄手机窗口、常规手机窗口和大字体；宽窗口允许双列，但正文对比不能挤成不可读。底部操作区避开安全区和键盘，浮动按钮不遮挡最后一条记录。有按下、禁用、加载、焦点反馈；动效简短且服务于层级，不做无意义入场动画或阻塞输入。

5. 验收与交付

每个改动页面检查加载、空、正常、错误、过期、提交中状态。回归项目切换、记录重试、会议冲突、归档恢复、行动结果、证据导航和简报已读，不因视觉改造回退已修复行为。

按改动运行相关测试、鸿蒙检查和HAP构建；API/Web未改时不机械运行无关全量检查。设备/模拟器可用时，安装运行并保存改前/改后截图及主线录屏；没有运行环境，明确未完成视觉/键盘验收，不把构建当作UI验收。

保留 ../../uireference/ 原图及用户未提交修改，不改变真实项目数据。专用验收数据独立保存，不写死到正式页面。不要部署、推送、上传参赛材料或使用历史临时凭据。

新增 ../acceptance/UI_REDESIGN_ACCEPTANCE_<实际日期>.md，记录：页面与参考对应、采用/舍弃的设计、组件变化、每个可见操作的数据与行为来源、测试、截图、设备条件和剩余限制。证据写到新的 ../../evidence/ui-redesign-<日期时间>/。

持续完成授权范围内的UI改造、调用适配和验证，再汇报实际成果；不要在只完成token或一个静态页面后宣布全部改造完成。
```
