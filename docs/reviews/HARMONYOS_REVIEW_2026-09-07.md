## 2. 影响归纳和最小修复顺序

1. **任务与导航**：先修返回刷新、弹层返回、截止日期、失败附件恢复。用户每一步都应能知道“保存了什么、下一步在哪里”。
2. **异步真实性**：删除伪证据，修正提醒承诺；并发完成与提案确认幂等化，明确部分同步、待确认结果。
3. **跨设备与输入**：目前宽屏策略主要是 840vp 以上限制正文/导航最大宽度；不是完整双栏适配。建议手机保留单列，平板做“列表—详情”，2in1 补键盘焦点。此为建议，不把单列本身认定为缺陷。
4. **无障碍**：不少控件已经补 accessibilityText/Selected 和按压效果，这是应保留的进展。自定义 Row/Column 按钮及 Stack 弹层仍需读屏、Tab/Enter/Escape、焦点恢复实测。不能仅凭语义属性认定通过。
5. **性能**：首页 1+3N 串行请求及未分页数据值得改；尚无帧率证据，不声称已经卡顿。搜索有响应序号保护，应保留，再考虑防抖/取消以减少请求。
6. **视觉一致性**：已有证据手账、语义色、统一图标和中文状态结构，无需全盘换皮。减少首页和工作台的重复统计，首屏聚焦“本次变化、一个最重要行动、依据入口”。大字体与深色当前未验收，不列想象中的溢出或对比度失败。

建议按依赖分三批：A) EVIDENCE-01、ASYNC-01、WRITE/TRUST；B) 返回刷新、附件收件箱、完整证据选择与日期；C) 设备矩阵及性能。先通过 A/B 再冻结复赛演示，避免边加功能边把核心事实链改坏。

最小验收：采纳→返回→新待办出现；完成→反复点击/并发→只生成一张复盘卡；断网/12 秒响应/迟到结果→状态可核对；拒绝通知权限→不得显示系统预约成功；通知冷启动/热启动/重启/撤销；附件失败→退出重进→仍可重试；大字体+软键盘+系统返回+读屏覆盖核心表单。

## 3. 安全边界，避免误报

直接调用本地 `/api/projects` GET 返回 200，匿名 DELETE 隔离测试项目返回 204，说明业务 API 没有应用身份/项目成员鉴权。**这不是本次证实的公网暴露**：仓库 Nginx 模板限制 `/api/` 来源 IP、屏蔽 settings，仅开放受鉴权的小艺路由。不要为连接手机直接移除 allow/deny。正式多用户/公网 App 需要身份与项目级授权；当前只是开发单用户边界。本次不访问或修改公网项目。

通知权限否定结果被缓存到 service 实例，用户后来开启权限也不重新查询；隔离 stub 已复现，须随前台恢复/发布重新核对。普通 publish 每次刷新高风险提醒都会被调用，未设置只提醒一次，应补更新策略并在系统侧核实是否重复打扰。

## 4. 复赛最值得新增什么

**首选一个主创新：“决策变更影响预览与成果更新闭环”。** 已有 W04 时态关系与 W05 可信回执，继续做普通聊天、更多模板或装饰性知识图谱，辨识度有限。以下是基于当前代码的产品判断，不承诺获奖，不使用旧蓝图分值冒充复赛最新评分表。

| 候选增量 | 当前已有 / 尚缺 | 最小实现需求与演示 | 取舍 |
|---|---|---|---|
| **A. 决策变更影响预览（主推）** | 已有决策关系提议/确认/撤销、当前/冲突/取代状态及回执；缺少会议前后差异、受影响待办与成果章节的统一预览和确认执行 | 输入“原方案 A 改为 B，提交提前两天”→显示原事实/新事实/来源、待确认冲突、影响哪项待办和成果；用户逐项确认；生成新版本并可回溯。建议分两段：先完成变化+任务影响，再加成果段落影响。 | 与已有架构最相容；先修提案绑定和幂等。不要把现有 W04 重新包装成全新完成品。 |

| **C. 小艺到 App 的真实连续任务（条件优先）** | 本地 adapter 与云工具配置已有；实施记录仍将真实调用对账/入口验证列为未完成 | “记下今天实验结果”→真实 card_id→App 同 ID 来源；“下一步做什么”→有证据的提案→人工确认→同 action_id→完成回写。保留取消、重复、错误项目测试。 | 作为鸿蒙亮点价值高，但受平台/设备约束；只有模拟器时先做平台调试与 App 对账，不能声称系统语音入口已验收。 |
| **D. 真正可靠的主动提醒** | 有规则引擎和本地 publish；缺少正确定时投递、完整权限/重启/取消与后台触发证据 | 到期或条件变化→只提醒一次→解释依据→确认行动→完成后不再打扰。增加用户可理解的“为什么现在提醒”。 | 是“主动 Agent”的可信基础；先完成既有承诺，提醒预算/偏好学习可后置。 |

**若只剩一个迭代周期：A 的“变化+待办影响”最小版 + B 的单段证据核验；C 只在已有设备/平台条件能闭环时加。** 不建议同时建设团队协作、完整知识图谱、更多模型、复杂人格、多端流转和 10 种成果类型。当前 API 无多用户授权，团队协作会显著扩大工程范围。

仍未形成原生闭环的常规需求：项目截止日期管理、里程碑/交付物完整创建管理、选择并撤销证据、卡片结构化纠错、成果人工编辑/导出、离线草稿/网络恢复。部分 Web/backend 已有，不要把“后端有路由”算作“鸿蒙端已完成”。这些需求按主创新所依赖的部分补齐即可。

## 5. 三分钟复赛演示建议与价值证据

- 0:00–0:30：展示真实项目原决策和原始依据。
- 0:30–1:15：导入一条改变决策的新实验/会议记录；显示冲突及旧结论仍保留。
- 1:15–2:00：预览受影响行动和成果；取消一次证明不会写入，再确认；重复提交证明不会复制动作。
- 2:00–2:40：打开新成果、点击引用核对来源；问一个证据不足的问题，展示正确拒答。
- 2:40–3:00：完成行动，返回项目，展示同一结果 ID 的复盘闭环。

这是新增功能完成后的目标脚本，当前并非全部可演示。以模拟器录像作为当前可达基线，真机通知/系统入口单独列证据。

建议做小规模真实项目评测：约 3 个真实项目、20–40 个自然问题及若干真实变更，由未参与规则编写的人标注。比较“普通检索问答”与“时态关系+回执+影响预览”：当前来源使用率、无依据断言、过期结论误用、完成一次变更需要的时间、重复写入数。预先固定题目和成功标准，报告失败样例与人数。现有 W04 60 组和 W05 40 组规则样例是回归证据，不是用户收益证明。

应保留的产品特征：证据手账、时间与来源、明确的人类确认、中文学术项目语境。

不应套用的通用风格：AI 渐变大头图、装饰性图谱、无意义玻璃卡片、满屏机器人聊天。

允许的 House Style：沉静蓝绿、细线证据脊柱、语义风险色、少量有目的的局部动效；不宣称这些是官方要求。
