## 记录功能定位

按钮回调设置 showCapturePanel=true；CaptureSheet 中有文字输入和 capture() 调用；MemoryService.capture 指向项目 captures 接口。当前实测故障是弹层没有出现，因此不能说“保存 API 已坏”，也不能因为未触发保存而宣称保存通过。

记录 Sheet 当前为未滚动的长 Column + FIT_CONTENT。修复打开后必须继续验证键盘弹出、大字号和小窗口下提交按钮可达。这是待验证风险，不是已复现的遮挡结论。

建议验收脚本：右上角记录/正文开始记录/缺口记录三个入口 → 同一录入面板 → 输入不少于 5 字 → 测试项目提交一次 → 新卡可见 → 再次点击不重复提交 → 断网提交保留输入 → 关闭/重进状态正确。先不对现有测试项目进行未经标识的记录操作。

## 页面用语建议

- “评估于 未知”改为失败时“暂未获取状态”，并给“服务暂不可用，重试”与可展开诊断，不把 HTTP 404 作为唯一面向用户的解释。
- “备赛准备度 0%”应说明是配置的材料清单覆盖度，避免让一般科研/课程项目也被当作参赛项目。
- “离线引擎”当前仍依赖后端 HTTP；可改为“规则引擎（无需模型 API）”，避免被理解为 App 断网也能用。
- “已同步”仅说明已完成的具体同步范围，不代表状态刷新等所有接口可用。
- 录入成功 toast 使用“已保存并生成记忆”，不要混用生命周期中的“归档”术语。
