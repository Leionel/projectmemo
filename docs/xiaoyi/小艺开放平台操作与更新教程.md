# 小艺开放平台 × ProjectMemo：从已有智能体到满足 S08 的跟做教程

这份教程以你当前画布为起点，先说明哪些节点能保留，再给出从纯文字原型到真实 ProjectMemo 调用的操作顺序。

> 适用对象：你已经在小艺开放平台创建了一个初步的对象（通常是“智能体”），但还不知道它怎样才算接到 ProjectMemo。
>
> 这不是一份“平台权限审计”。它回答的是：**我现在已经建了一个，下一步该配置什么；每一步怎样对应 S08；什么做完才可以说 S08 通过。**

## 先说结论：保留工作流，最终迁移到云 A2A

你现在创建的是**工作流模式 Agent**。先不要删除，也不要改成 LLM 模式。当前路线分为两个阶段：

1. **现在用工作流模式完成交互原型和接口联调。** 工作流负责识别四项 S08 业务请求和两类辅助请求、调用 ProjectMemo 适配层、组织回答，并在创建行动项前要求用户确认。
2. **Backend 具备公网 HTTPS 地址后，新建云 A2A 模式 Agent 作为最终接入。** 云 A2A 直接复用 ProjectMemo 已有 Agent、Memory、Evidence 和 `AgentRun`，避免在小艺平台复制第二套业务逻辑。

端 A2A 需要关联 HarmonyOS 应用/元服务，并在应用内提供 Agent 服务。当前项目只有 DevEco 模拟器、尚未完成正式应用身份与真机小艺验证，因此不把端 A2A 作为 S08 当前主线。

S08 要求的不是在控制台做出一个能聊天的“忆程”外壳，而是让小艺能安全地调用 ProjectMemo 的四项已有业务能力：记录、检索、查项目状态，以及在用户确认后创建行动项。

```text
用户对小艺说一句话
        ↓
小艺中的 ProjectMemo 智能体识别意图
        ↓
调用一个受控的 ProjectMemo 工具适配层
        ↓
ProjectMemo 现有 Backend 和数据库执行/读取
        ↓
把带证据、带确认状态的结果返回给小艺和 App
```

因此，你已经创建的工作流是第一阶段入口；下一步要给它接受控工具、做确认并留下调用证据。不要在工作流中另建一套长期记忆、项目状态或任务数据库。

## 三种 Agent 模式怎么选

小艺开放平台提供 LLM、工作流和 A2A 三种核心开发模式。三者是不同的编排方式，不是同一个 Agent 的三个必选组件。[华为智能体开发模式说明](https://developer.huawei.com/consumer/cn/activity/incentive/ai/)

| 模式 | 业务逻辑在哪里 | 适合什么情况 | ProjectMemo 结论 |
|---|---|---|---|
| **LLM 模式** | 主要由平台模型、提示词和知识完成 | 问答、顾问、内容生成，外部业务状态较少 | **不选。** 它会和 ProjectMemo 自有 Agent 重复，且难以保证项目状态、证据和写入确认一致 |
| **工作流模式** | 平台用可视化节点编排判断、工具调用和回复 | 固定流程、明确分支、快速接 HTTP/插件服务 | **当前阶段使用。** 用于交互原型与四工具联调，不在平台保存第二份业务事实 |
| **A2A 模式** | 小艺通过 AgentCard 和 A2A 协议调用第三方 Agent | 第三方已经有 Agent、任务状态和工具体系 | **最终选择云 A2A。** 直接复用 ProjectMemo Backend；端 A2A 留到应用身份和真机条件具备后再评估 |

云 A2A 和端 A2A 属于 A2A 模式的两个落点：云 A2A 调用部署在公网的 ProjectMemo Agent；端 A2A 调用 HarmonyOS App 内的 Agent 服务。华为的端 A2A 控制台流程要求关联应用/元服务并导入 AgentCard。[端 A2A 模式官方说明](https://developer.huawei.com/consumer/cn/doc/service/device-a2a-0000002640106106)

## 当前工作流能不能接入

**可以接入，但必须满足一个条件：工作流中存在可调用外部 HTTP 服务、端云插件或等价工具的节点。** 如果当前工作流只有大模型、条件判断和文本回复节点，它只能做对话演示，不能读写 ProjectMemo 的真实数据。

工作流不能访问下面这些开发地址：

- `http://127.0.0.1:4400`
- `http://localhost:4400`
- DevEco 模拟器使用的宿主机映射地址

这些地址只在你的电脑或模拟器网络中有效。要完成平台接口联调，需要先部署一个受控的公网 HTTPS 适配层。适配层再调用 ProjectMemo Backend，并负责平台鉴权、用户到项目的授权映射、确认凭证、幂等和 `AgentRun` 审计。

在公网适配层完成前，你可以保存工作流结构、提示词、参数和测试样例，但只能把状态标记为“工作流草稿完成”，不能标记为“S08 已接入”。

## 先看懂你现在这张工作流

你发来的画布不是空白稿，基础骨架已经有了。问题不在“节点太少”，而在于紫色大模型节点目前只生成文字，整个画布没有调用 ProjectMemo Backend 的插件节点。

| 你画布里的节点 | 现在实际做什么 | 保留还是改 | 具体处理 |
|---|---|---|---|
| **开始** | 接收本轮用户输入 | 保留 | 只使用平台默认的用户输入；不要新增一个让用户填写 `projectId` 的参数 |
| **意图分类** | 把输入分到多个分支 | 保留并重配 | 改成 `record_memory`、`query_memory`、`inspect_project`、`create_action`、`generate_artifact`、`other` 六类 |
| **主动介入评估器** | 当前看起来直接根据分类结果生成评估文字 | 保留但移动逻辑位置 | 它必须先拿到 `inspect_project` 插件返回的真实项目状态，再判断是否建议介入 |
| **提问器** | 询问用户“接受并创建 / 稍后处理”等 | 保留 | 只放在行动预览之后，用于收集明确确认；不要让它代替写入接口 |
| **选择器** | 根据提问器结果走 IF/ELIF/ELSE | 保留并改条件 | IF=确认创建，ELIF=稍后处理，ELSE=取消；只有 IF 连接 `commit_action` 插件 |
| **碎片记录分支** | 紫色大模型节点，只会生成“已经记录”之类的文字 | 改名并加插件 | 改名为“整理记录参数”，其后新增 `record_memory` 插件；没有插件前不得回复“已记录” |
| **长期记忆** | 使用小艺自己的长期记忆能力 | 从项目查询主路断开 | 它不是 ProjectMemo 数据库；项目历史必须通过 `query_memory` 插件查询。该节点最多保存称呼、回复偏好等非项目事实 |
| **成果生成分支** | 生成成果类文本 | 暂时保留为独立 P1 分支 | 它不属于 S08 四工具验收；不要让它替代 `generate_artifact` 的真实 Backend 调用 |
| **大模型_2** | 名称和职责不清楚 | 改名 | 如果它只负责把插件结果说成人话，改名为“行动结果回复”；它不能负责创建行动 |
| **文本处理组件** | 汇总各分支文字 | 有条件保留 | 试运行确认未执行分支不会输出 `null`、空模板或旧值；否则每条分支各用一个回复节点，不要强行汇总 |
| **结束** | 返回最终结果 | 保留 | 使用文本返回模式；至少要返回一段用户可见文本 |

从这张图看，当前状态只能写成：**工作流结构原型已完成，ProjectMemo 真实数据接入尚未开始。** 华为工作流中的插件节点才负责调用外部工具；大模型、长期记忆和文本处理节点本身不会访问你的 Next.js API。[插件节点官方说明](https://developer.huawei.com/consumer/cn/doc/service/plug-in-node-0000002437625906)

  │    → 项目状态回复
  │
  ├─ create_action

### 第 0 步：先存档，不要直接覆盖

在工作流编辑页打开版本管理，先保存当前画布的手动存档。

1. 将存档名称写成 `before-projectmemo-api-v1`。
2. 将说明写成 `保留当前纯工作流原型；下一版本新增 ProjectMemo 插件调用`。
3. 保存后再改节点和连线。

如果平台当前页面没有手动存档入口，先使用工作流导出功能下载 JSON。不要把带账号、密钥或测试用户信息的导出文件提交到公开仓库。

### 第 1 步：配置开始节点

打开 **开始** 节点，只把平台默认的本轮用户输入连接到 **意图分类**。官方文档把开始节点定义为工作流输入入口；工作流模式下，不要依赖只能在试运行中填写的自定义输入参数。[开始节点官方说明](https://developer.huawei.com/consumer/cn/doc/service/start-nodes-0000002471344161)

你的第一版不要在开始节点添加下面这些字段：

- `projectId`
- `platform_user_id`
- `confirmation_token`
- `api_key`

这些字段来自平台可信上下文或服务端，不应让用户通过自然语言自由填写。当前只有一个测试项目时，先在服务端把测试身份绑定到固定测试项目。

### 第 2 步：重配意图分类节点

打开 **意图分类** 节点，删除含义模糊的原分类，按下面的名称、说明和样例逐项新增。意图分类节点负责分流，不负责生成业务结果。[意图分类节点官方说明](https://developer.huawei.com/consumer/cn/doc/service/intent-classification-node-0000002437625914)

| 分类名称 | 描述 | 正样例 | 容易混淆但不属于它 |
|---|---|---|---|
| `record_memory` | 用户明确要求把一段新进展保存进项目 | “记录一下，接口已经联通”“把这段会议结论存下来” | “之前记录的接口方案是什么”属于查询 |
| `query_memory` | 用户查找过去保存的决定、资料、讨论或证据 | “上周演示方案怎么定的”“找一下登录接口的记录” | “现在有什么风险”属于状态检查 |
| `inspect_project` | 用户询问当前进度、风险、停滞、材料缺口或下一步 | “这个项目现在卡在哪里”“检查一下答辩风险” | “给我建个修复待办”属于创建行动 |
| `create_action` | 用户提出创建行动项，或回应上一轮行动确认 | “把联调问题建成待办”“确认创建”“先不要创建” | 普通记录不能进这个分支 |
| `generate_artifact` | 用户要求生成周报、总结或答辩材料 | “生成本周项目周报” | 它是 P1，不计入 S08 四工具最小闭环 |
| `other` | 闲聊、越界请求或无法判断的输入 | “你是谁”“帮我查天气” | 不调用 ProjectMemo 写接口 |

如果节点有“补充提示词”或等价字段，填入：

```text
只负责分类，不回答用户问题。
优先根据用户本轮主要动作分类。
“记录/保存/记一下”且内容是新信息时选 record_memory。
“之前/上次/找一下/回忆”时选 query_memory。
“现在/风险/进度/下一步/停滞”时选 inspect_project。
“创建待办/建立行动/确认创建/稍后/取消”时选 create_action。
无法确定时选 other，不要猜测。
```

完成后，把六个输出口分别连接到对应分支。不要让一条输出线同时连接“长期记忆”和“碎片记录”，否则一次请求可能产生两份互相矛盾的回复。

### 第 3 步：创建 ProjectMemo 云插件

在添加插件节点前，先在小艺开放平台的资源库创建一个云插件或账号当前提供的等价外部工具资源。平台 UI 可能要求手动定义工具，也可能允许导入接口描述；以你控制台显示的方式为准。

插件命名为 `projectmemo_backend`。第一版定义以下六个工具：

| 工具 | 方法和目标路径 | 工作流传入 | 成功时至少返回 |
|---|---|---|---|
| `resolve_context` | `POST /xiaoyi/v1/context/resolve` | 平台可信身份、项目名称（可选） | `project_ref`、`project_title`、`authorized` |
| `record_memory` | `POST /xiaoyi/v1/memories` | `content`、可信上下文 | `card_id`、`title`、`summary`、`created_at` |
| `query_memory` | `POST /xiaoyi/v1/memories/search` | `query`、`limit`、可信上下文 | `results[]`，每项含真实 `card_id` 和摘要 |
| `inspect_project` | `POST /xiaoyi/v1/projects/inspect` | 可信上下文 | `status`、`risks[]`、`actions[]`、`data_time` |
| `create_action`（预览） | `POST /xiaoyi/v1/actions` | `confirmed=false`、`title`、说明、优先级、可信上下文 | `proposal_id`、预览字段、短期签名凭证 |
| `create_action`（提交） | `POST /xiaoyi/v1/actions` | `confirmed=true`、`proposal_id`、幂等键 | `action.id`、`status`、`due_at` |

上表是小艺适配层的契约，不是把项目内部 API 原样暴露出去。截至 2026-08-26，仓库已经实现 `record_memory`、`query_memory`、`inspect_project` 和两步 `create_action` 四项能力，均具备固定项目授权、Bearer 校验、限流、幂等回执和 `AgentRun` 审计。当前实现仍未部署到 ECS，也没有小艺平台真实调用证据，因此只能标记为“Backend capability ready”，不能标记为 S08 A/B 级通过。

这里出现六个工具，不代表 S08 变成六项能力。对应关系是：

| S08 对外能力 | 工作流内部调用 |
|---|---|
| 记录项目碎片 | `resolve_context`（需要时）+ `record_memory` |
| 检索项目记忆 | `resolve_context`（需要时）+ `query_memory` |
| 检查项目状态 | `resolve_context`（需要时）+ `inspect_project` |
| 创建行动项 | `resolve_context`（需要时）+ `prepare_action` + 用户确认 + `commit_action` |

`resolve_context` 是统一授权步骤；`prepare_action` 和 `commit_action` 是把一次危险写入拆成“预览”和“确认后提交”。用户看到的仍然是四项能力。

插件服务地址必须是平台能访问的 HTTPS 地址。不要填写 `127.0.0.1`、`localhost`、`10.0.2.2` 或局域网 IP。插件鉴权严格使用控制台实际支持的方案，不要把密钥写进大模型提示词或普通工作流变量。

### 第 4 步：改造碎片记录分支

把截图中的 **碎片记录分支** 改成参数整理节点，再在它后面添加插件节点。

1. 将节点改名为 **整理记录参数**。
2. 将用户提示词设为开始节点的原始用户输入。
3. 将系统提示词改成下面这段，并选择结构化输出；如果平台不支持结构化输出，就只输出原始待记录内容，不要输出成功句子。

```text
从用户输入中提取需要保存的项目新信息。
只输出 JSON：{"content":"..."}。
删除“记录一下”“帮我保存”等命令词，但保留原始事实、日期、数字和专有名词。
不要总结成另一条事实，不要生成 card_id，不要声称已经保存。
```

4. 在其后新增 **插件** 节点，选择 `projectmemo_backend.record_memory`。
5. 将 `content` 映射到 **整理记录参数** 的结构化输出。
6. 将插件成功输出连接到新的 **记录结果回复** 节点。
7. 将回复模板写成：`已记录到「{{project_title}}」：{{title}}（卡片 {{card_id}}）。`
8. 将插件失败输出写成：`记录失败：{{safe_error_message}}。本次没有创建知识卡片。`

如果插件没有返回 `card_id`，该分支不能使用“已记录”“保存成功”等措辞。

### 第 5 步：改造长期记忆分支

把截图中的 **长期记忆** 从项目查询主线断开。小艺长期记忆适合保存偏好，不是 ProjectMemo 的项目知识库。

1. 从 **意图分类** 的 `query_memory` 输出口连接一个新的 **插件** 节点。
2. 选择 `projectmemo_backend.query_memory`。
3. 将开始节点的原始输入映射到 `query`。
4. 将 `limit` 固定为 `5`。
5. 在插件后新增 **检索结果回复** 大模型节点。
6. 将用户问题和插件的 `results[]` 同时传给该节点。
7. 使用下面的系统提示词：

```text
你只能根据 results 回答。
每个项目事实后标注对应 card_id。
results 为空时只回答“没有找到可引用的项目记录”。
不得使用平台长期记忆补充项目事实，不得虚构引用。
```

如果你希望保留原 **长期记忆** 节点，只允许它保存“用户喜欢简短回答”“默认使用中文”等偏好；不要把项目结论、风险、行动状态写进去。

### 第 6 步：改造主动介入分支

截图中的 **主动介入评估器** 现在位置过早。它必须先读取真实项目状态，再做判断。

1. 从 `inspect_project` 输出口新增 **插件** 节点。
2. 选择 `projectmemo_backend.inspect_project`。
3. 将插件输出连接到 **主动介入评估器**。
4. 删除该节点直接使用意图分类 `reason` 作为事实来源的配置。
5. 将系统提示词改成：

```text
你根据 inspect_project 的结构化结果整理项目状态。
只能使用 status、risks、actions 和 data_time 中的内容。
先说明当前状态，再列出最多 3 个风险和 1 个下一步建议。
没有风险时明确说明“当前数据未发现风险”。
不得生成不存在的卡片、行动或完成状态。
```

6. 将用户提示词映射为：开始节点原始问题 + `inspect_project` 插件完整输出。
7. 将该节点直接连接 **项目状态回复**，不要在每次状态查询后都强制弹出行动确认。

如果要让系统主动建议创建行动，先让适配层执行 `prepare_action` 并返回预览，再进入提问器。不要让大模型自己生成一个无法追踪的确认 token。

### 第 7 步：把提问器和选择器用于真正的两步确认

截图里的 **提问器 → 选择器** 方向是对的，但前后缺少 `prepare_action` 和 `commit_action` 两个插件节点。

1. 从 `create_action` 输出口连接 **整理行动预览** 大模型节点。
2. 限制它只输出 `title`、`description`、`priority` 和 `due_at`；不要写数据库。
3. 在其后添加 `projectmemo_backend.prepare_action` 插件。
4. 将插件返回的 `proposal_id` 和 `confirmation_token` 保留在当前会话变量中，不要展示完整 token。
5. 将插件返回的预览内容连接到 **提问器**。
6. 将提问文字设置为：

```text
准备创建行动项：
标题：{{title}}
说明：{{description}}
优先级：{{priority}}
截止时间：{{due_at_or_none}}
请选择：确认创建 / 稍后处理 / 取消。
```

7. 在 **选择器** 中配置三个互斥分支：

| 优先级 | 条件 | 后续节点 |
|---|---|---|
| IF | 提问器结果等于“确认创建”或平台返回的对应选项值 | `projectmemo_backend.commit_action` |
| ELIF | 提问器结果等于“稍后处理” | 文本回复“已暂缓，本次没有创建行动项。” |
| ELSE | 其他结果，包括取消、空值和无法识别 | 文本回复“已取消，本次没有创建行动项。” |

8. 在 `commit_action` 插件中传入 `proposal_id`、`confirmation_token` 和以平台 request ID 生成的幂等键。
9. 仅当插件返回 `action_id` 后，回复：`已创建行动项 {{action_id}}：{{title}}。`
10. 在插件超时或失败时回复：`创建失败，本次结果未知，请先在 ProjectMemo 行动列表检查，避免重复创建。`

选择器的 ELSE 不能连接写入节点。用户说“好吧”“看看再说”或回复空文本时，一律按未确认处理。

### 第 8 步：处理成果生成和兜底分支

**成果生成分支** 暂时不属于 S08 最小闭环。保留它时，明确标为 P1 原型。

1. 将 **成果生成分支** 改名为 **成果生成原型（未接 Backend）**。
2. 在回复首句说明：`下面是未保存的草稿。`
3. 在没有调用 ProjectMemo 成果接口前，不要返回 artifact ID，也不要说“已生成并保存”。
4. 为 `other` 新增固定回复：`我目前可以记录项目碎片、检索项目记忆、检查项目状态，以及在确认后创建行动项。`

### 第 9 步：配置文本处理和结束节点

你现在把多个分支汇入同一个 **文本处理组件**。这种接法可以保留，但必须先验证未执行分支的空值行为。

1. 将每个分支的最终输出统一命名为 `answer_text`；如果平台不允许同名变量，分别命名并在模板中只引用当前分支输出。
2. 试运行每个意图一次，检查文本处理结果是否出现 `null`、`undefined`、旧对话内容或多个分支拼接。
3. 如果出现串值，为每个分支分别添加文本/输出节点，再直接连接 **结束**，不要继续共用一个文本处理组件。
4. 在 **结束** 节点选择用户可见的文本返回模式，不要只返回一个内部变量对象。工作流模式若没有可见文本，用户侧可能得到空响应。

最终回复必须满足：读操作带证据 ID，写操作带新对象 ID，失败时明确失败，未确认时明确没有写入。

小艺测试输入

### C. 最后补行动两步确认和 20 轮对照

当前仓库已把 `prepare_action` / `commit_action` 收敛为同一个 `POST /xiaoyi/v1/actions` 的两步协议：首次 `confirmed=false` 只生成签名提案，第二次 `confirmed=true` 才写入 Action。部署到公网 HTTPS 后，仍需在平台调试环境验证首次零写入、确认后恰好新增一条以及重复提交不重复创建，再运行本文的 20 轮对照表。

工作流四能力通过平台测试后，再评估迁移云 A2A。应用未上架不会阻止工作流插件或云 A2A 调用公网 Backend；它主要限制的是需要应用身份、签名或真机入口的端 A2A/ArkTS Skill 路线。

## S08 到底要交付什么

把下面四项看成智能体的“工具清单”，而不是四段聊天提示词。

| S08 能力 | 用户会怎么说 | ProjectMemo 的真实业务落点 | 小艺应该返回什么 |
|---|---|---|---|
| `record_memory` | “记录一下：接口联调已经完成。” | `POST /api/projects/{id}/captures` | 新建卡片的标题、卡片 ID、来源和是否成功 |
| `query_memory` | “上周定的演示方案是什么？” | `GET /api/projects/{id}/cards/search` | 命中的卡片 ID、标题和摘要；不能编造引用 |
| `inspect_project` | “这个项目现在有什么风险？” | 项目详情、介入和指标读取接口 | 当前状态、风险/介入、下一步和数据时间 |
| `create_action` | “把联调问题建成待办。” | `POST /xiaoyi/v1/actions`（先 `confirmed=false`，再 `confirmed=true`） | 第一次返回待确认的行动预览；确认后返回唯一的 action ID |

**ProjectMemo 是事实源，小艺只是入口和编排层。** 小艺不能另存一份项目状态，也不能在没有证据卡片时补写“历史结论”。

## 配置工作流工具或 A2A 能力契约

无论当前使用工作流工具节点，还是后续迁移到云 A2A，ProjectMemo 对外提供的业务能力和安全边界都保持一致。工作流把下列能力配置为外部工具；A2A 则把它们写入平台要求的 AgentCard 和协议实现。

### 第 1 步：先固定一个测试项目

在开始任何工具配置前，选一个专门用于联调的 ProjectMemo 项目。

1. 在 ProjectMemo App 或 Web 中创建/选定一个测试项目。
2. 记下它的 `projectId`，但不要让小艺模型自由猜测或接受任意 `projectId`。
3. 在适配层把“小艺测试用户”绑定到这个项目，或要求用户明确选择已获授权的项目。
4. 为测试项目准备至少两张可检索的知识卡片和一条可见的风险/介入记录。

这样做是为了让平台调试中的每次调用都能和 App 逐项对照。任何未授权项目 ID 都应被拒绝，而不是返回空数据后继续执行。

### 第 2 步：在智能体描述中写清范围

在“智能体描述”“系统提示词”“角色设定”或同等栏目中，填入下面的内容。若你的控制台将“描述”和“指令”分开，第一段放描述，后面的规则放指令。

```text
你是 ProjectMemo（忆程）的项目记忆助手。

你只帮助已授权项目完成四件事：记录项目碎片、检索已有记忆、查询项目状态与风险、在用户明确确认后创建行动项。

回答涉及项目事实时，必须使用工具返回的卡片、状态或 ID；没有结果时直接说明“没有找到可引用的项目记录”。
不得猜测项目 ID、跨项目读取数据、透露密钥或内部鉴权信息。

创建行动项必须分两步：
1. 先展示标题、说明、优先级和截止时间（如有），并问“是否确认创建？”
2. 只有用户明确回答“确认/是/创建”后，才调用写入工具。

用户没有确认、表达犹豫、改变任务内容或授权校验失败时，不得创建行动项。
```

这段指令只约束模型行为，**不能替代服务端授权和确认校验**。真正的安全边界仍在后面的适配层。

### 第 3 步：添加四项工具契约

平台表单名称可能是“工具”“能力”“服务”“技能”或 AgentCard 中的能力项。无论名称是什么，按下表填写等价信息。

表中的字段是 ProjectMemo 对平台适配层的目标契约，**不是让你把现有本地 API 原样暴露出去的 Schema**。平台生成的 AgentCard 或工具 Schema 优先；字段名称不同时保持含义一致即可。

#### 工具 1：`record_memory`

这个工具把用户明确要求保存的内容写入当前授权项目。

| 栏目 | 填写内容 |
|---|---|
| 名称 | `record_memory` |
| 一句话说明 | 将用户确认要保存的一段项目进展写入当前已授权项目，并返回知识卡片。 |
| 何时调用 | 用户明确说“记录”“保存”“记一下”“把这条进展写进项目”。 |
| 必填输入 | `content`：5–5000 字的项目内容。 |
| 可选输入 | `source_type`：例如 `xiaoyi`、`voice`。项目 ID 由已授权上下文提供，不让模型填写。 |
| 成功输出 | `card_id`、`title`、`summary`、`source_type`、`created_at`。 |
| 不该调用 | 用户只是提问、总结或询问已有记录时。 |

建议先用这句调试：`记录一下：小艺接入方案今天完成了能力映射，明天开始工具适配。`

#### 工具 2：`query_memory`

这个工具检索当前授权项目中的真实知识卡片，并返回可引用的结果。

| 栏目 | 填写内容 |
|---|---|
| 名称 | `query_memory` |
| 一句话说明 | 在当前已授权项目的知识卡片中检索与问题相关的证据。 |
| 何时调用 | 用户问“之前怎么定的”“找一下某个方案”“上周的风险是什么”。 |
| 必填输入 | `query`：1–500 字的检索问题。 |
| 可选输入 | `top_k`（或兼容字段 `limit`）：1–8，默认 8；`type`：需要按卡片类型过滤时才传。 |
| 成功输出 | `results[]`，每项含 `card_id`、`title`、`excerpt`、`score`/`retrieval_mode`（平台和后端实际支持时）。 |
| 不该调用 | 用户要求写入、创建待办或问当前实时风险时。 |

建议先用这句调试：`找一下我们给小艺接入定过哪些边界。`

计划把它定义为 Hybrid Search，但当前 S04 的真实语义检索 Gate 尚未通过。你可以先完成工具声明和接口联调，不能把返回结果宣传为“真实语义召回通过”。

#### 工具 3：`inspect_project`

这个工具读取当前授权项目的实时状态、行动项和风险信息。

| 栏目 | 填写内容 |
|---|---|
| 名称 | `inspect_project` |
| 一句话说明 | 读取当前项目的进度、行动项、介入/风险和最近更新时间。 |
| 何时调用 | 用户问“现在进展如何”“有什么风险”“下一步做什么”。 |
| 必填输入 | 无；项目由已授权上下文确定。 |
| 可选输入 | `include`：`summary`、`actions`、`interventions`、`metrics` 中的一个或多个。 |
| 成功输出 | 项目标题、状态摘要、未完成行动、介入/风险、数据时间和关联 ID。 |
| 不该调用 | 用户要求找某段历史原文时；那应调用 `query_memory`。 |

建议先用这句调试：`检查一下当前项目的风险和最该做的下一步。`

#### 工具 4：`create_action`

这个工具只在用户确认行动预览后执行写入。

| 栏目 | 填写内容 |
|---|---|
| 名称 | `create_action` |
| 一句话说明 | 在用户明确确认后，为当前已授权项目创建一条行动项。 |
| 何时调用 | 仅在用户已对展示的行动预览明确确认之后。 |
| 必填输入 | `confirmation_token` 或同等确认凭证；`title`。 |
| 可选输入 | `description`、`priority`（1–5）、`due_at`、`source_card_id`、`source_intervention_id`。 |
| 成功输出 | `action_id`、标题、状态、创建时间、幂等键/请求 ID。 |
| 不该调用 | 用户第一次提出“建个待办”、只是在讨论、或确认不明确时。 |

建议先用两轮调试：

1. `把工具适配的联调问题建成一个优先级 4 的待办。`
2. 小艺展示预览并问是否确认后，再回答：`确认创建。`

### 第 4 步：把“创建行动”做成两步，而非一次写入

这是 S08 最容易被误解的一项。用户第一次说“创建待办”时，不应调用数据库写接口。

```text
用户：“把联调问题建成待办。”
        ↓
智能体整理为 proposed action（只在会话/短期确认记录中保存）
        ↓
小艺：“将创建：联调工具适配；优先级：4。是否确认创建？”
        ↓
用户：“确认创建。”
        ↓
适配层验证确认凭证、项目授权和幂等键
        ↓
ProjectMemo 写入 Action，并返回 action_id
```

内部 `POST /api/projects/{id}/agent/tools` 仍要求 `confirmed` 为真；当 `confirmed: false` 时会返回 `CONFIRMATION_REQUIRED`。仓库新增的 Xiaoyi 适配层在其外部 `POST /xiaoyi/v1/actions` 中补上了预览和签名提案：第一次只返回 `proposed_action`，第二次确认后才转调现有 Action 写入服务。直接把小艺连到内部 `/agent/tools`，不能满足这条计划要求。

### 第 5 步：接服务端时，配置的是适配层，不是本机地址

目前 ProjectMemo 的业务 API 位于本机开发环境；小艺平台无法访问 `127.0.0.1`、`localhost` 或 DevEco 模拟器中的 `10.0.2.2`。这些地址只适合 App 模拟器访问本机服务。

你要实现的服务边界如下：

```text
小艺平台调试请求
        ↓（平台规定的鉴权格式）
https://受控域名/xiaoyi/...     ← 新增：小艺适配层
        ↓（项目授权、限流、审计、幂等）
ProjectMemo 内部 API/服务
        ↓
数据库与 AgentRun
```

在控制台配置工具服务时，用下面的对照表，而不是把内部 API 一条条复制进去。

| 控制台栏目 | 你要填的含义 | 当前能否填写真实值 |
|---|---|---|
| 服务/工具名称 | 上一节的四个稳定名称 | 可以 |
| 描述、触发样本、输入输出 | 上一节的契约和调试语句 | 可以 |
| 回调/服务地址 | `https://你的受控域名/xiaoyi/tools/<tool-name>` 这一类适配层地址 | 适配层和公网 HTTPS 完成后才可以 |
| 鉴权方式 | 严格使用平台实际提供的方式；服务端负责验签/验 token | 先看当前控制台/协议，不要自行编造请求头 |
| 超时、重试、签名字段 | 以平台导出的 Schema 或协议为准 | 不要沿用本机 Demo 的默认值 |
| 发布/测试用户 | 先保存草稿或测试版本 | 不要把未联调服务发布上线 |

适配层需要完成的事情是清晰且有限的：

1. 验证来自小艺平台的请求身份。
2. 将平台用户映射到允许访问的 `projectId`。
3. 将平台输入转成 ProjectMemo 内部 API 所需字段。
4. 对写请求校验确认凭证和幂等键。
5. 把 `source: "xiaoyi"`、平台 request ID、工具名、`confirmed`、关联卡片/行动 ID、状态和耗时写入 `AgentRun.trace`；不得记录密钥。
6. 将内部错误转成可读但不泄露实现细节的工具结果。

当前 `AgentRun` 已增加外部 request ID 和结果回执；四项 Xiaoyi 适配能力都会记录工具名、来源、确认状态、关联 ID、状态和耗时。真实服务地址、平台支持的鉴权方式和平台调试结果仍待部署/验证，不能把本地专项测试当成平台接入完成。

## 意图路线何时使用

如果你创建的是“意图框架”中的自定义意图，而不是带工具的 Agent，也没有建错；它适合做“用户对小艺说一句话后，打开 ProjectMemo 对应页面并传参”。

但它不是本 S08 四项能力的替代品：意图只负责识别和调起，`record_memory`、`query_memory`、`inspect_project` 与带确认的 `create_action` 仍需要在 App 或服务端的适配层里完成。

你可以把意图当作辅助入口，例如：

```text
“打开忆程，查看答辩项目的风险”
        ↓
自定义意图识别 project / view 参数
        ↓
启动 ProjectMemo 的项目详情页
        ↓
App 自己读取项目状态
```

华为当前意图自测试资料要求把测试账号加入真机测试用户组，并在 HarmonyOS 6.0.0(20) 及以上真机的小艺中验证。因此，在你只有 DevEco 模拟器时，可以完成意图注册、参数和 App 处理逻辑的准备，但不能把模拟器中的 App 页面当作“小艺真实入口通过”。[意图自测试官方说明](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/intents-skill-all-rec-dp-self-validation-decorator)

## 为什么现在不以 ArkTS Skill 作为主路线

华为当前 ArkTS Skill 文档标注从 API 26 开始支持；当前 ProjectMemo 工程为 API 24。不要为了“看起来接了小艺”而把 API 26 的代码或 `bundleType: skill` 片段直接塞进现有工程。

等 S08 主路径验证完成且决定升级 API 后，再单独评估 ArkTS Skill 的兼容性、签名、模拟器回归和真机验证。它是备选架构，不是当前待补的一行配置。[ArkTS Skill 开发指导](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/arkts-skill-development-guide)

## 用 20 轮测试证明四项能力真的一致

平台服务地址可用后，在测试项目上做 5 个循环；每个循环跑四个场景，共 20 次。每一次都同时保存小艺调试记录、适配层日志/AgentRun 和 ProjectMemo App 画面。

| 每个循环的场景 | 小艺侧输入 | ProjectMemo App 必须看到 | 失败时先查什么 |
|---|---|---|---|
| 1. 记录 | 一条新的、可辨识的项目进展 | 新知识卡片及相同 `card_id` | 项目授权、卡片写入、平台 request ID |
| 2. 检索 | 用刚记录的关键词提问 | 结果引用真实卡片，不是泛泛回答 | `query`、项目范围、检索结果和引用 ID |
| 3. 状态 | 询问进度、风险或下一步 | 状态/风险/行动数与 App 同一时刻一致 | 数据时间、项目 ID、风险/介入读取 |
| 4. 行动 | 提出创建请求，再明确确认 | 首次无新增 Action；确认后恰好新增一条 | 确认凭证、幂等键、写入前后数量 |

每轮最少记录这些字段：

```text
轮次：01–20
平台版本/能力 ID：
平台 request ID：
工具名：
projectId（可脱敏）：
confirmed：true / false / 不适用
返回的 card_id / action_id / intervention_id：
App 对照结果：PASS / FAIL
AgentRun ID、provider、状态、耗时：
失败原因与截图位置：
```

## 你的模拟器条件如何计入验收

只有 DevEco 模拟器并不妨碍你做 ProjectMemo App 和后端的一致性验证，但它限制了你能宣称的层级。

| 证据层 | 你现在可以做到什么 | 能否算 S08 通过 |
|---|---|---|
| 平台草稿配置 | 智能体、能力描述、参数和测试样本保存 | 不能；这只是配置完成 |
| 服务端/适配层测试 | 四工具契约、授权、确认和审计的自动化/接口测试 | 不能单独通过；这是后端证据 |
| DevEco 模拟器 | App 显示同一张卡片、风险和行动项 | 只能证明 App 闭环，不是小艺系统入口 |
| 平台调试环境 | 20 轮工具调用与 App 对照成功，Unauthorized Action Rate = 0 | 可作为计划定义的 **A 级** 证据 |
| 真机小艺系统入口 | 从真实小艺唤起/调用并端到端成功 | 才是 **B 级**；当前没有真机时标为 `UNVERIFIED` |

不要用 App 内聊天、普通 Web 请求成功，或一张控制台配置截图来代替 B 级。华为把 Agent、Skill 与 A2A 作为不同的开放接入能力；你需要以实际选中的路线和真实调用证据为准。[Harmony Intelligence 开放能力概览](https://developer.huawei.com/consumer/cn/harmonyos-ai)

## 常见困惑

下面的问题用于判断工作流配置、接口联调和正式接入之间的边界。

### 我已经创建了一个智能体，为什么还不能说“接入完成”？

因为智能体目前只是入口。S08 的完成条件还包括四个工具的真实调用、项目授权、两步确认、`AgentRun` 审计，以及 20 轮和 App 的对照。缺少其中任一项，都只能说“平台对象已创建”。

### 我能不能先把 `http://127.0.0.1:4400` 填到工具回调里？

不能。该地址只代表运行小艺平台浏览器/服务的机器自身，不是你的开发机；`10.0.2.2` 也只是 DevEco 模拟器访问开发机的专用地址。等受控公网 HTTPS 适配层部署好后再填真实回调。

### 当前的 `create_action` 接口已经有 `confirmed`，是不是就完成两步确认？

仓库内的 Xiaoyi 适配层已经补上了“预览 + 签名提案 + 确认后幂等写入”：第一次 `confirmed=false` 不创建 Action，第二次必须提交未过期且绑定项目的 `proposal_id`。但平台配置和公网部署尚未完成，仍不能据此宣称小艺平台接入通过。

### `query_memory` 有结果就算 S04 和 S08 都完成吗？

不算。它可以证明接口通了；要宣称真实混合/语义检索通过，还要完成 S04 的标注集 benchmark 和 Gate。S08 受 S04 阻塞，不能用一两次检索演示越过这个 Gate。

### 小艺页面没有和本教程一模一样的按钮，怎么办？

看栏目承担的功能，不看单个按钮文案：先确认是 Agent/A2A/工具还是意图框架，再按本教程的“名称、描述、触发条件、入参、出参、服务地址、测试”逐项映射。你可以把当前对象详情页截图发来（遮住账号和密钥）；再据此补一段与你的控制台完全一致的点击路径。
