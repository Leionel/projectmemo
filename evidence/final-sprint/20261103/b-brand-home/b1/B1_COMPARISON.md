## 3. 两款的信息结构

### A · 原委托四问工作包
- 左侧：主张 + 副标题 + 两个 CTA + 公开示例说明。
- 右侧：同一委托的工作包卡片；用户切换“离开时 / 期间 / 回来后”（默认回来后），始终按四问组织：**原委托 / 依据 / 变化 / 等你**。
- “查看依据”行内展开 3 条原文；“回到原委托”锚点到五步示例。
- 交互：`role=tablist` + roving tabindex，方向键/Home/End 切换；每次切换真实替换 panel 内容与 `aria-selected`。

### B · 来源变化 → 判断改变 → 等待用户的因果镜头
- 左侧文案与 CTA 完全同 A。
- 右侧：一条纵向因果链 01 来源 → 02 变化 → 03 判断改变 → 04 等你；来源用可展开的原文 chip，判断改变用“原来 / 现在”对照。
- 交互：点开任一来源展开原文（`aria-expanded`，焦点保持）；“回到原委托”锚点。

## 4. 三轴判断（内部评审，不是用户测试结论）

| 轴 | A | B |
|---|---|---|
| 定位辨识：3 秒内更像“持续项目 Agent”还是笔记/待办工具 | **强**。卡片顶部给出同一项目/委托与“等你确认”，四问第一行即“原委托”，主张与产品镜头互相证明。 | 中。视觉重心先落在“来源→变化”的推理过程，需要顺着链读两步才看到“委托仍在、等你决定”；更像“证据审阅”而非“项目接续”。 |
| 现在该做什么 | **强**。“等你”始终是第四行并高亮，待处理动作一句话可执行；回来后默认态直接展示。 | 中。最后一步才出现“等你”，且与前面三步同一视觉权重。 |
| 实时与示例区分 | 强。卡片 kicker“内置公开示例”、行内“冻结示例，不连接服务器”、页脚“本页交互不调用模型”。 | 强。同样具备示例标识；但链式叙事更容易被误读为“系统刚查过”，因此需要在 S2 使用更多解释空间。 |
| 依据可达性 | 强。行内展开 3 条原文，不离开页面。 | 强。chip 展开单条原文。 |
| 移动端 | 强。卡片为独立移动版式（四问纵排、44px 目标），不是桌面图缩放。 | 中。纵向因果链在 390 下高度更长，关键“等你”落到首屏之外更远。 |

说明：以上是设计评审判断；**3 位非开发者 10 秒理解测试未执行（NOT_RUN）**，没有用模型或开发代理冒充受试者。真实用户反馈保留为未验 Gate。

## 5. 裁决

**选定 A 作为生产 Hero 信息结构**（原委托四问工作包 + 三阶段切换，默认“回来后”），理由：

1. 首屏目标首先是让人明白“项目被保留了下来、现在轮到我决定”，A 的四问把“原委托/依据/变化/等你”同时放在一屏，满足 3 秒辨识；B 需要顺序阅读，3 秒内更像“证据审查工具”。
2. A 的“回来后”默认态与产品核心承诺（人可以下线、回来接得上）直接同构；B 的默认态是推理过程，承诺需要读者自行归纳。
3. A 在移动端更短，“等你”更容易进入首屏附近；B 的因果链在窄屏高度过长。
4. A 的交互（阶段切换 + 行内依据）在键盘与降级路径上更简单，符合减少动画/无 JS 可读的要求。

**B 不弃用**：其“来源变化 → 判断改变 → 等待用户”的因果镜头正是本计划 S2 必须讲清的内容；B2 将把该因果结构并入“离开以后发生了什么”一节（横向四步 + 判断改变高亮），Hero 只保留 A。弃选的是“B 作为首屏主结构”，不是 B 的信息本身。

## 6. 失败判据核对

| 判据 | 结果 |
|---|---|
| 两款只换色 | 通过：信息结构、信息层级、默认画面与交互模型均不同 |
| 访客认为示例正在跑真实 Worker | 未发现：两款首屏均可见“公开示例/不调用模型”，且无倒计时、心跳、假进度 |
| 移动端只能放大桌面图 | 通过：两款均为独立响应式版式（竖向四问 / 因果链） |
| 依据不可达 | 通过：A 行内展开 3 条原文，B 可展开任一来源原文 |
| CTA 不工作 | 通过：主 CTA 落到 `#experience` 锚点；“进入工作台”指向登录/工作台路径 |
| 没有记录弃选方案 | 通过：第 4、5 节记录 B 作为首屏弃选的理由与复用去向 |

## 7. 残余限制

- 原型路由使用应用全局导航（非首页营销页头），两款完全一致，不影响 A/B 判断；生产 B2 会使用首页自己的 SiteHeader。
- 原型只覆盖 Hero，不含生产首页其余段落；跨屏叙事在 B2 一次成型。
- 本机 dev 环境截图含 Next 开发覆盖物；生产构建/性能在对 after 的检查中另记，不用 dev 数据代表线上。
