`20261023-live-recovery/results.json` 和 `budget.json` 原样来自用户上传的 ECS 文件；内容是合成项目，模型调用真实。文件哈希与审阅摘要见同目录 `assessment.json`。

- 原始三项委托：首次一项工程闭环成功、两项协议失败。
- 修复后：新协议探针通过，恢复原来两项失败委托并生成草稿、成果和归入回执；两次恢复都沿用原 Mission 和补料。
- 当前三项最新结果均完成工程闭环，其中第一项来自旧版本。恢复尝试不能算作新版本从零的三次独立成功。
- 账本累计23次真实调用、记录费用上界0.188372元，未知usage为0。原授权仍是累计60次/10元，本轮归档和P1-A实现不增加付费调用。
- 两份新草稿的引用范围、摘录哈希、声明位置和声明哈希已核对。语义Judge未启用，草稿仍为NEEDS_REVIEW；合成91%不是真实实验结果。

`task-manifest-v1.json` 冻结十类任务及当前测试入口。状态为入口映射和本次轨迹覆盖，不代表十类真实模型均通过。任务范围改变时另增v2，保留v1；重试保留失败及同一账本。人工标签、用户理解测试、真机与平台验收分别保持空值或未验收。既有运行入口继续使用 `npm.cmd run mission:verify`，不建立新Runner。

## P1-A 交互约定

使用者回到一个已有项目，想知道当前关注的目标、忆程在等待什么、点击哪里继续。当前分散入口存在不同排序及RUNNING行遗漏。本轮将导航选择收回同一个有界只读服务：补料、批准、已知来源失效、暂停/失败、高优先提醒、运行/就绪、行动、普通提醒、记录进展。同类优先个人关注委托，仍保留上位等待事项。

对象是本用户可访问项目中的现有Mission、提案或行动。GET只读；个人关注设置只更新ProjectMembership.focusMissionId，不能更改任务生命周期、云模型授权或批准状态。只允许OWNER关注自己在该项目尚未结束的委托。设置可清除；终止/删除/撤权后的指针不再作为当前目标。规则依据：`rule/smallest-intervention`、`rule/navigation-vs-action`、`rule/name-object-scope-consequence`。

`ProjectAgentContext` 包含项目目标指纹、Mission/planRevision、原问题和待批准ID、实体版本、输出修订、理由、观察时间、内容指纹及失败原因。观察指纹不含读取时钟。读取失败明确不可用或部分可用，不能因此建议新建任务；跨用户查询与迟到响应不能带回旧身份内容。规则依据：`rule/cover-reachable-states`、`rule/error-states-recovery`。

Web概览、Reentry和全局焦点共享服务；全局最多对六个已授权候选项目聚合并明确hasMore。ArkTS读取同一DTO，不复制排序。保留原导航、原Mission深链和历史Reentry字段；旧客户端忽略新增字段。阶段记录与安排折叠到辅助区域，主事项保留一个主操作。无用户测试数据时不宣称“60秒理解”已验证。

新迁移仅为ProjectMembership增加可空关注字段；必须先按部署脚本备份后增量迁移，不能执行seed/db:setup。`PROJECT_AGENT_CONTEXT_ENABLED=false`回退原展示；历史指针不删除。构建、隔离测试、真机操作、生产部署分别记录，不互相代验。
