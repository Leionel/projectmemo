## 本轮修复（由上一轮真实失败驱动）

1. **每调用输出预留释放**：`settleUsage` 在结算时释放 `reservedOutputTokens`，只保留真实 token 用量；此前长期连续 Mission 会因累计预留（默认 24k）在 12 次调用后被误判 `BUDGET_EXHAUSTED`。
2. **v2 决策输出上限**：v2 单次决策从 2000 提升到 3000 tokens（截断修复窗口仍 4000），`modelAdapter` 直接使用上下文给出的上限；降低长草稿 JSON 被截断的概率。
3. **协议修复窗口**：v2 允许两次格式修复（v1 仍一次）。
4. **方法门槛拒绝的一次引导重试**：`skillRepair` 提供 `requiredTool: read_project_material` 与 `sourcePointers`（sourceId/sourceHash），每 contextVersion 最多一次；避免“越过阶段保存”直接终止。
5. **相同私有稿去重**：内容与来源完全相同的连续保存返回上一版并记 `OUTPUT_UNCHANGED`，不产生无意义新版本。
6. **改道正文要求**：deliverable-creation SKILL 要求改道/受限后的新版本在正文首段写出当前工作重点原话。

离线测试：fixture/http 均 40/40 + 24/24；全量测试与 tsc/lint 见同目录日志。
