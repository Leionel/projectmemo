# R4 Agent UX：核心页面与跨端交互合同

本方案落实 [统一 Roadmap](D:/Projects/hongmen/planning/r4-agent-ux-integration/R4_AGENT_UX_INTEGRATION_ROADMAP.md) 的三个任务：回来了解变化、查清当前问题、交代持续工作。当前实现差异见 [代码对账](D:/Projects/hongmen/planning/r4-agent-ux-integration/CODE_DEMO_AUDIT.md)。所有新增字段、文案和布局均为待实施方案。

## 1. 页面职责与渐进展示

保留“焦点／项目／记忆／行动”四个入口。焦点帮助选择下一步；项目维持工作语境；记忆帮助核对与纠正；行动保存用户要做的事及结果。Conversation 是这些对象里的协作入口，不另设必须维护的“聊天空间”。

| 层级 | 用户应能回答的问题 | 默认内容 | 展开内容 |
|---|---|---|---|
| 第一层：当前事项 | 哪个项目，发生什么，现在等谁，我能做什么？ | 一句目标／变化、一条状态原因、一个主要动作；必要的停止入口 | 其余事项集合 |
| 第二层：判断与协作 | 为什么这样判断，缺什么，我能怎么纠正？ | 影响决策的依据、未知、具体问题／批准／结果 | 条件比较、原文、相关历史 |
| 第三层：审计与设置 | 读了哪一版，做过哪些步骤，授权和预算是什么？ | 按需打开 | 原工具步骤、source hash、版本、完整回执、累计预算与许可 |

这是信息层级，不是强制渲染三张卡。模型仍可按问题组合原十类语义块，选择顺序、比较维度与强调。明确批准时，操作对象、后果、重要条件和费用范围属于第一／二层，不能折叠藏起。

产品默认用语：Mission→“委托”，working objective→“当前重点”，WAITING_OBSERVATION→“等待新变化”，Memory/Dream→“已记录／待核实”，Always On→“持续跟进”。具体错误原因说人话，错误码留详情。原始状态和 ID 只在需要核对时显示。

## 2. 首次使用：先办成一件小事

新用户进入焦点时，空态只提供“从一个项目开始”，附一个可直接修改的例子：“把最近的进展记下来，问问下一步。”已有项目则优先选用户进入的项目，不能用最近访问项悄悄覆盖当前 scope。

1. 用户创建／选择项目，贴一段记录或上传材料；成功后看到原记录，失败保留输入。
2. 用户提出自己的问题，例如“根据这些结果，明天该先排查什么？”Agent 先使用已获许可的项目资料；只在需要外部资料或云上下文时展示原授权。
3. 回答包含有用判断、缺失条件和下一步。证据不足时清楚说缺口；不为凑首次成功强行建 Action 或 Mission。
4. 用户可以继续调查、补材料、改理解，或确认一个原提案。需要跨会话持续推进时，才提出“把这件事作为委托继续跟进”，展示原许可边界。

引导不要求用户先认识 Memory、GoalGap、Worker 或十种工具。没有模型／工具／worker 条件时，保留可用的记录与原入口，并明确当前可完成的范围。不能用演示数据自动填充真实项目。

## 3. 今日焦点：一个首要事项，其他按需看

桌面保留两栏能力：主栏是当前事项和协作，辅栏是项目语境／其他事项。窄屏和手机先展示事项摘要，再进入同一 Conversation；不同时挤入两栏，也不让输入框遮住原问题。

示意内容按真实投影填充：

> 算法竞赛 · 当前重点：先保证周五演示稳定  
> 还缺目标设备的安装结果。上次 CI 已通过，不能据此确认设备可用。  
> **补充安装结果**　查看依据　调整重点  
> 其他事项 3 项

“补充安装结果”必须绑定原问题或原 Action；没有绑定则显示“打开原委托”。“查看依据”打开确切来源或证据集合，不能把普通 Mission 列表伪装成原文。若确实只能打开委托，文案就是“查看委托”。

主动作随真实情况变化：回答问题、审阅方案、记录结果、查看进度、核对当前状态。普通讨论留为次级入口。Hero 从列表中去重，不再同时出现同一事项的大卡和小卡。统计数字退到集合入口，不占首屏中心。

排序采用 Roadmap S1 的共享投影；跨端相同快照返回相同 originalRef。用户关注偏好是排序输入，不改变事实／授权。集合范围不完整时说“当前范围建议先处理”，提供查看更多；不显示虚假的全局完成比例。

| 可达状态 | 页面行为 |
|---|---|
| 加载 | 保留骨架和当前项目，不抢输入焦点；旧快照标核对中 |
| 空态 | 区分“没有待处理”与“还没有资料”；不自动制造提醒 |
| 部分读取失败 | 展示已知事项和未覆盖范围，可重读；不写“一切正常” |
| 无重要变化 | “上次核对后暂无重要变化”，显示核对时间；不产一条新聊天消息 |
| 当前项失效 | 保留旧内容的历史标识，停用旧操作并获取当前对象 |
| 无权访问／换账号 | 清除该身份私人缓存和草稿；不显示上一账号的项目摘要 |

规则依据：rule/one-primary-action、rule/preserve-mental-model、rule/cover-reachable-states。

## 4. 委托详情：目标、进展、协作和结果

首屏结构是“要办什么 → 当前结论／进展 → 下一步”。“当前重点”与原正式项目目标并列但不等同；用户可以先稳演示，原验收条件不会消失。最近结果只选有用的一项，其余在变化经过中保留。

### 4.1 状态到行为的共享映射

| 原记录和证据 | 显示状态／责任方 | 默认动作 | 必须保留的条件 |
|---|---|---|---|
| READY，尚未领取 | 待执行／Agent | 查看当前计划 | 没有健康证据不写“后台正常”；显示最后核对时间 |
| RUNNING，当前有效 lease | 正在调查／Agent | 查看进展 | 就近停止；进度来自持久步骤，不展示虚构百分比或隐藏推理 |
| WAITING_INPUT，未解决的用户问题 | 等你补充／用户 | 回答原问题 | 精确 question ref、当前版本；旧 QUESTION 已解决则不再展示为待答 |
| WAITING_INPUT，明确获准等待观察 | 等待新变化／Agent 的获准检查 | 查看跟进条件 | 上次观察、下一检查、期限／预算；不虚增待回应计数 |
| WAITING_APPROVAL，当前有效提案 | 等你确认／用户 | 审阅该方案 | exactApprovalRef；明确是创建行动、固定核算还是其他原操作 |
| PAUSED，用户暂停 | 已暂停／用户选择 | 恢复前核对 | 原权限／期限／预算／版本重验；暂停不自动撤销所有来源 |
| FAILED，已知失败 | 这一步未完成／按原因 | 查看原因及恢复条件 | 已做结果保留；只有原服务明确可重试时才显示恢复 |
| 原外部请求 UNKNOWN | 状态待核对／系统结算 | 查询原请求／查看已知结果 | 不换 requestId 重派；费用和预算保留预占 |
| 授权、来源、预算或指令到期 | 需要重新核对／具体责任方 | 核对许可／额度／方向 | 不能以“恢复”隐式扩大授权或清账 |
| SUCCEEDED，正式条件通过 | 委托已完成／可复盘 | 查看结果 | 单列草稿状态、Action/resultCardId 和现实效果；无凭据不说现实成功 |
| 旧记录无法分辨等待原因 | 等待条件需核对／未知 | 打开原委托核对 | 不猜用户必须答复；保留原数据 |

多个条件并存时，明确当前阻塞和仍可合法继续的部分。例如缺目标设备结果时，Agent 仍可在授权预算内读已有 CI 或整理证据；不因一个未知条件停止全部可做调查，也不把它当已解决。

### 4.2 页面模块

原 GoalQuestion、批准、readback、输出和设置继续复用，按当前状态出现：

- 顶部：原目标、当前重点、状态原因、核对时间；调整重点／暂停或停止易达。
- 正文：当前问题／批准／有用结果；没有协作事项就展示简短进展，避免空审批列表。
- 依据：支持、反证、尚未知的条件与覆盖；按需打开来源。
- 变化经过：原事件、指令、结果的时间序列；创建、开始、完成分别展示。
- 详情／设置：原步骤、来源许可、持续策略和累计预算；修改许可前后差异可读。

预算耗尽显示已用、未知预占和待完成内容；“调整预算”是原 BudgetReview，不是另开任务。重新规划仍使用原 replan/context/planRevision，不能复制 Mission 重置消耗。

### 4.3 回执

“行动已创建”“核算已执行”“已保存你报告的结果”“委托完成条件已通过”“现实效果已独立验证”是不同事实。UI 只选择原服务能证明的层级；后两项不可由模型自由文字升级。

一条批准消费后原位变为回执，保留同一 execution/approval/Action ID。记录结果后显示 resultCardId 的原文入口和剩余未知。刷新／重试回读同一效果；网络丢回包先查询或重放原请求。显示小数可做明确精度格式化，原值和计算规则留在详情。

## 5. Conversation 与动态生成式 UI

复用 [AgentMessageBlocks](D:/Projects/hongmen/components/AgentMessageBlocks.tsx)、[原生 renderer](D:/Projects/hongmen/harmonyos/entry/src/main/ets/components/AgentMessageBlocks.ets)、presentationRuntime 和原 catalog。

模型决定该轮是否需要证据、比较、问题、变化或回执等语义块，以及顺序／强调；服务端决定哪些原对象和动作当前合法。不是每轮都显示“目标／依据／未知／下一步”四张固定卡，也不显示所有可用工具。正文必须能独立阅读，复杂结构有可读 fallback。

### 5.1 调查进行中

显示实际已完成动作，例如“已读实验记录”“正在核对第 7 页”；没有精确页就只说“正在读取文档”。展示当前阶段、停止和已知结果；不把模型 token 流当作工具完成。无 gain、证据足够、需用户材料、预算限制时都可结束。用户选择深入模式仍沿原根预算和工具选择，不能变成硬编码检索流程。

### 5.2 合法动作

现有 action 类型 OPEN、ASK、PREVIEW、CONFIRM、DECLINE、REFRESH 按原 binding 执行。发布时绑定、点击时重验；模型不能填任意 URL、payload、owner 或新权限。Direction/withdraw 默认调用原 Continuity 控件；确需进入消息 action 时，只在原 union 加白名单控制分支。

同一消息内主要操作最多强调一个；两个互斥方案用原 comparison/selection 先选后预览。非互斥步骤可以继续存在，但布局先让用户知道当前真正需要自己处理什么。

### 5.3 就近纠正的自然语义

| 用户说法／选择 | 持久对象与行为 | UI 反馈 |
|---|---|---|
| “这个项目本周先稳演示” | 符合原 Directive Admission 且范围、期限明确时直接采用；原 turn 重新协调 | “本项目本周先保证演示稳定”；可查看原话、范围、到期与撤回 |
| “他说以后应该先做新功能” | 引述／背景，只作为资料或解释候选 | 不改变当前重点；若与请求相关，明确这是谁的建议 |
| “以后都按这个来” | 永久性或 scope 不清；一次澄清具体对象、范围／期限 | 单个行内问题，保留原话；未答前不扩大目标或授权 |
| “停止”／“先暂停这次调查” | 当前对象唯一时立即走原控制；无需模型解释来延迟停止 | 展示已接收及已知在途请求；结算后状态来自原服务 |
| “这个数字只是我说的，还没验证” | 定位原 claim 和 revision，纠正解释，触发同范围重评 | “已改为你的报告，尚未独立核实”；不删除原记录 |
| “原文件错了，换成这个版本” | 原附件修订／新 Capture，保留历史并使读集失效 | 显示版本变化和需重核的结论 |
| “以后别参考这个判断” | 明确对象和 scope 后 SUPPRESS_USE；派生消费同受限制 | “后续判断不再引用”；历史仍可查看，恢复需重核 |
| “少提醒我这件事” | 原 Anchor/GoalQuestionPreference/USER Policy | 显示延后／停止提醒的范围；不悄悄停止调查或停用证据 |
| “把它改成已验证” | 可保存用户确认／自报，不能凭指令制造客观证据 | 说明当前记录层级，展示仍缺的验证 |

身份认证、原话存在、模型解释正确是三件事。NL 明确指令可直接生效；模型抽取不自动形成永久目标。修订期间迟到模型／工具结果受原 generation、lease、intent hash 和预算规则处理，UI 的“已过期”标记不代替服务端协调。

### 5.4 同一证据入口承接现有工具

以下是共同阅读合同，保留各工具自己的证据边界和下一步，不把它们统一成“已核实”卡片。

| 工具／来源 | 默认显示 | 按需核对 | 合法后续与禁止推断 |
|---|---|---|---|
| PR-6 Search/Fetch | 标题、来源、阅读层级、结论支持／反证／未定 | 原 URL、抓取时间、快照、引用片段、ResearchCoverage | 有授权和预算时可继续选查询／Fetch；搜索摘要不能冒充全文，网页建议不是指令 |
| CT-2 GitHub/CI | 仓库、已观察提交、检查／失败任务的范围 | 原 SHA/attempt、connection revision、jobs/log 及 coverage | 模型按缺口决定是否读日志；CI 绿不完成 Action，不证明部署或设备成功 |
| CT-4 文档深读 | 原附件、实际物理页、引用片段 | 文件 hash、修订、实际读取页范围；扫描／表格缺口 | 继续选页、比较原文；不支持页跳转时给明确页码和原件，不能假装 OCR 已完成 |
| CT-6 论文检索 | DOI／标题、元数据或实际全文层级 | 原 metadata 响应、父来源、OA／附件定位和未知条件 | 元数据可指导后续阅读；不能把摘要／作者自报写成已读实验全文或方法复现 |
| CT-5 实验指标 | 数值、单位、升降方向、条件是否可比 | 数据列、split/seed/环境、原 CSV/JSON 修订与定位 | 条件未知保留未知；核算可以帮助比较已给数字，不能证明研究方法有效 |
| CT-5 固定核算 | 待批准的具体固定 job 或原执行回执 | 输入 hash、镜像／脚本身份、限制、UNKNOWN／失败及输出 | 原批准后才运行；创建、开始、完成分开；不能扩展为任意 shell 或训练 |
| CT-7～10 后续工具 | 先沿上述状态／证据／批准槽位 | adapter 交付时补具体环境、页面、账号、资源版本与 effect receipt | 未实现时说明缺口；不显示假在线健康、假 Browser 轨迹或通用外部写按钮 |

引用动作先回到当前合法来源；来源过期后保留历史标识和重新调查入口。抓取时间、论文日期、记录日期、指令生效区间分别展示，不用一个“最近更新”替代。

## 6. Memory / Dream：内容、变化和演化

全局记忆默认按项目分组和明确 scope 展示；项目内只看该项目。已记录／待核实是内容筛选，不是两套存储。变化经过与方法经验作为相关详情／筛选，避免四个同等主导航。

### 6.1 每项最小内容

显示主张、来源类型及原对象、最近证据变化、当前有效性、Agent 使用状态。用户自述、模型推断、原工具观察、独立验证分开。未知状态不使用绿色勾；CURRENT 可译“当前记录”，不能直接译“真实”。

“待核实”只读聚合现有 GoalGap/Investigation、Output INFERENCE、Decision 候选，不新建 Dream 数据库或队列。已有 AgentExperience 保留独立的适用条件、SHADOW/ACTIVE 状态、支持案例／反例与撤销入口，不把所有推测都包装成经验。

展示身份包含 owner/project/originalRef/revision/claim locator。没有唯一来源的二手总结，显示“出处需核对”，可以继续调查；不把它计为独立证据。三份同根摘要按一条来源链解释，不能显示成“三个独立来源一致”。

### 6.2 事实与使用策略分开

| 操作 | 原服务 | 用户可理解的结果 |
|---|---|---|
| 补充新证据 | 原 Capture／附件修订、ImpactJob | 新材料到达，相关判断需重核 |
| 纠正解释 | 拟增原 Continuity 的 INTERPRETATION_CORRECTION 类型和 target/locator metadata，复用 SET/WITHDRAW/有效视图 | 哪一句、怎样理解、只对哪个范围生效；不改变工作目标或授权 |
| 原记录被替代／反驳 | 原 Temporal relation proposal/confirm/revoke | 新旧记录和关系都可追溯；关系需原证据 |
| 用户确认内容 | 原 memoryLifecycle | “你确认了这条记录”；不会标独立核验 |
| 不再参考 | 原 SUPPRESS_USE/sourcePolicy | 后续消费排除该来源及派生；历史仍可读 |
| 归档 | 原 memoryLifecycle | 从常用视图收起；不改变事实有效性 |
| 忽略当前推测 | 原候选／主题的个人显示偏好 | 收起这条建议；不是永久证据停用 |
| 整理／撤销整理 | 原 consolidation preview/confirm/revoke | 预览合并对象和关系；原回执可撤销且不覆盖后来的独立修改 |
| 激活／撤销经验 | 原 experience service | 仅符合资格的 SHADOW 可激活；撤销停止新注入 |

原“修改卡片摘要”不能作为无版本 guard 的快捷事实纠正；若用户需要更正事实，优先用新记录／修订与关系链。快捷确认上线前补当前 source/relation 版本检查和幂等探针。

### 6.3 演化触发与闭环

触发来自新增／修订证据、用户纠正、原 Action 结果、有效期越界和授权 Mission 的有意义观察。失效标记使用原 ImpactJob、Temporal Ledger、sourcePolicy；失效不等于立即付费重算。需要语义判断时，交回同一调查及其合法预算。

重复候选整理采用原服务的有界规则；用户主动整理时展示预览。不因打开页面、每天凌晨、同样的信息重复到达而运行模型“做梦”。新的经验只读视图不能隐式调用当前 listExperiences 的 sync 写入；同步与读取边界在原服务中补全。

纠正之后展示“哪些结论需重核／哪些已重新调查”，不能只弹“已保存”。来源抑制覆盖 Investigation、摘要、Artifact 再利用、经验注入、待确认提案及新视图；来源未知时只作线索。恢复使用不复活旧审批；须在当前 scope／版本／时间下重新核对。

## 7. 持续跟进与注意力

用户在原委托选择持续跟进时，一次核对：目标、截止、已授权来源／连接、工具范围、累计模型／工具／HTTP 上限、检查间隔、安静时段、什么情况下找用户。跟进不代表无限预算或自动外部写入；已授权范围内的合法只读工具继续自主选择。

原许可应展示一句可读摘要，例如：“到周五，检查已收录提交的 CI；有关键问题时留在这里。预算累计计算。”具体数字来自原 policy。需要追踪新 head 时说明沿现有仓库信号刷新，不能承诺尚未实现的全仓持续发现。

| 用户意图 | 行为与展示 |
|---|---|
| 暂停调查 | 原 pause；停止新派发，已发请求按原 UNKNOWN／结算处理；显示已做结果 |
| 恢复调查 | 原 resume/continuation；重验期限、scope、连接 revision、预算和版本 |
| 稍后提醒 | 原 LATER／snooze；调查是否继续由原许可决定 |
| 不再提醒此主题 | 原 STOP；新来源 revision 不擅自复活提醒 |
| 撤销持续许可 | 原 policy 撤销；不清已用预算，不删除历史结果 |
| 我已看到 | 原 attention SEEN，带版本／decisionId／requestId；不等于批准或完成 |

无重要变化只更新核对时间；获准 HTTP 仍记成本，无新模型、无新提醒。普通变化合并到原任务／主题；多个入口不能对同一私人事项重复扣 USER 打断预算。

静默结束、用户本地预算日切换、到期和指令有效边界，即使无新事件也重新判断。关键事项在私人收件箱保持可见；不能靠全部压下取得低噪声。通知接受／曝光／已读／批准分别读取原回执。

系统通知能力单独表达：“应用内可见”“本设备通知已允许”“当前不支持后台投递”。现有共享 Intervention 本地通知、Action 日历提醒与 CT-3 私人 Mission 不混成一个通道。关闭 App 后是否能收到，必须有对应设备和渠道证据。

## 8. 跨端协作与 ArkUI 落点

当前源配置 target 6.1.1(24)、compatible 6.1.0(23)，module 声明 phone/tablet/2in1；输入包括触控和大屏键盘／指针。设计沿项目现有资源，未据 Demo 推断新的官方视觉标准。

| 场景 | Web | HarmonyOS App | 卡片／小艺／潜在穿戴 |
|---|---|---|---|
| 日常回来 | Focus 主事项＋按需语境栏 | GlobalFocusPanel 单列，进入原 FocusConversation | 只提供最小状态、核对时间和打开 App |
| 深入证据 | 原引用、文档／指标比较详情 | 原 ConversationWebSource、AttachmentViewer；复杂比较展开全页 | 不直接展示私有全文或批准载荷 |
| 改方向／撤回 | 原 Continuity 行内编辑 | 原 Continuity 组件，短表单／必要时 sheet | 正式身份／交互未验收时回 App |
| 批准／记录结果 | 原 binding + 原回执 | 原 ApprovalSheet／Action 结果入口 | 小艺／卡片不携带审批令牌；穿戴不预设审批能力 |

ArkUI 实施位置：GlobalFocusPanel/GlobalFocusPresentation、FocusConversation、ConversationContinuity、MissionPanel/MissionReadbackView、AgentMessageBlocks；DTO 在 models，调用在 services，页面保留原对象 ID。不要用整个 Conversation version 重建表单，原 message/block 稳定身份与 Preferences 草稿继续使用。

原项目已启用系统字体跟随，上限 1.3；约 16fp 正文／至少 44vp 操作目标作为当前项目基线。验收深色、字体放大、长中文标题、键盘弹出、读屏名称／顺序、返回行为和外接键盘。更大字体需求须实测并决定是否提高上限，不能写成已支持任意缩放。Web 覆盖桌面及 360/390/430 宽、125% 文本、键盘完整路径。

小艺当前 inspect 使用测试用户＋Mission allowlist；resume 只允许现有 LOW_RISK_READ_ANALYZE 等原条件，不扩为 BOUNDED_INVESTIGATION。正式多用户平台身份、分发与真机留渠道 Gate。穿戴先选目标系统／机型，当前不新增 wearable 声明。

## 9. 失败、失效和权限的共同交互

- 草稿按 user/conversation/object 身份保存，退出／换账号清除；网络失败不清空输入，恢复后不自动提交旧草稿。
- 409 说明哪个对象／来源／指令已变化，提供“读取当前内容”；读回后再决定。401 回登录并清私人缓存；403/404 不自动换到相似项目。
- 到 nextBoundary、回前台、重连、切项目或账号时重新取有效视图。缓存含身份、scope、source/intent/reusePolicy 版本，最大寿命不越最近边界；无事件到期同样失效。
- 用户修改在途调查时，显示“已接收新方向，正在按当前条件继续”；实际可继续时间取决于原 generation/lease。迟到响应只能进入原结算／历史路径，不能重新发布旧批准。
- 来源撤权后保留合法历史查看与未知说明；新消费走 sourcePolicy。已经提交的原请求保留历史回执，新 requestId 不绕过当前授权。
- 未知 UI 版本／block／action 有正文 fallback 和原对象入口；缺少当前 binding 时不渲染可执行确认。
