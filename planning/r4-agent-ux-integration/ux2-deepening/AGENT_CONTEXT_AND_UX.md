# UX-2 R2：Context Composer、工具与双端体验

## 1. Composer 的职责

在原 workspaceContextService、Investigation 和 Mission contextBuilder 中共用“有效记忆选择＋来源资格＋覆盖”规则。Composer 组织可用上下文，不决定固定工具顺序，也不成为新的 Planner。

最小输入为 actor、原 scope／原对象、当前问题、原正式目标、Effective Intent、预算与工具可用性、已读 manifest 和原恢复信息。输出包括：

```text
contextBinding(scope, intentHash, reusePolicyHash, source/claim heads, nextBoundary)
sections(authorityKind, content, refs, coverage, applicability, freshness)
openCommitments, relevantHypotheses, experienceAdvisories
missingInformation, excludedReasons, truncation, availableReadRefs
```

系统策略、用户原话、用户纠正、原始观察、模型推断和方法建议分区输入。记忆文本不能放入 system 区冒充授权；用户纠正是需遵循的解释反馈，但其中对现实的声明仍可能只是自报。

## 2. 选择与分层读取

始终保留当前有效目标／限制／STOP、当前问题、必要的未完成承诺和授权边界。其余按任务相关、时效、来源可用、证据适用性、缺口价值和预算选择，不能按“被提到次数”决定真假。

先用有权目录和有效 Digest 定位；对决定性的结论读取具体 claim 和证据片段；需要判断支持关系、比较条件或处理纠正时回原文。深度由原 GoalGap/Investigation 的下一信息需求决定，允许直接结束或请求私有信息。

原上下文的头尾裁剪、目录上限和新 Digest 覆盖均需显式记录。不能把未读部分当作没有支持。Composer 可给可读取的原 refs，但不生成未授权工具、任意 URL 或“必须先做 A 再做 B”的固定计划。

多项目问题按 scope 分段；当前项目事实不直接变成另一项目条件。用户明确迁移思路时创建目标项目的新候选，链接原出处，重新检查适用条件；来源和工具权限不迁移。账户偏好只包含明确的非业务偏好，项目细节不默认写入账户综合。

## 3. 何时可以用、何时必须再查

| 状态 | 允许用法 | 必须避免 |
|---|---|---|
| 当前原观察，scope/版本/适用条件满足 | 作为对应主张的证据候选，必要时精确引用 | 来源可读就称支持；工具成功就称现实成功 |
| 当前 Digest，manifest 可验证 | 快速重建背景、原因和未完成承诺；按需要展开 | 用摘要代替决定性原文；摘要成为独立支持 |
| 有限支持的 Hypothesis | 提供调查方向和预测，显示条件与反证 | 当事实、指令或自动执行许可 |
| SHADOW/ACTIVE 方法经验 | 按原适用条件给建议；保留案例和反例 | 跨项目自动激活、修改系统策略或扩大工具许可 |
| 纠正后的旧解释／来源换版 | 作为历史并说明变化，读取当前原文重评 | 刷新页面后旧结论再次成为当前推荐 |
| 血缘未知／覆盖不足／条件不可比 | 说明未知，主动选合法工具补缺口或问必要问题 | 把 UNKNOWN 当 FALSE；伪造独立来源或可比性 |
| 撤权／SUPPRESS_USE | 保留合法历史展示，排除新推理和新提案消费 | 换成摘要／Artifact／经验绕过限制 |

记忆要改变实际调查：例如因发现 split 不同，下一步可读原 CSV 条件或询问缺失划分，而不是立即核算；因已有当前原结果，允许直接回答或结束；因新反证出现，撤销旧比较前提并在同一任务改道。

## 4. 工具观察怎样进入长期认知

| 工具 | L0 保留 | L1/L2 演化 | L3 和界面 |
|---|---|---|---|
| PR-6 Search/Fetch | 原 query、URL／快照／hash、scope revision、reading level、ResearchCoverage | 可形成触发、支持／反证候选；网页文字不成为用户意图 | 来源卡分摘要／正文，缺覆盖可继续搜索；保留迭代查询 |
| GitHub/CI | 授权连接／revision、固定 SHA/attempt、checks/jobs/log、覆盖 | 变化可触发“是否影响演示”的假设，绿 CI 不完成部署结论 | 原观察与日志展开；新采纳先过 F07；权限变化即时失效 |
| PDF/文档 | 原附件修订、fileHash、物理页、章节／表格片段 | 主张引用精确页面／条件；修订时只重核相关结论 | 同一页／版本阅读与比较；渲染／页跳转需要真实能力探针，不能用打印页码冒充 |
| 论文研究 | DOI、元数据／摘要或实际全文、父来源、版本与未知状态 | 论文主张可触发研究假设；作者自报与项目验证分开 | 明确是否已读全文；发现项目条件不同可保持不可比 |
| CSV/JSON 指标 | 文件／行列定位、单位、方向、split/seed/环境及覆盖 | 同条件结果可支持／反驳预测；异条件进入 INCONCLUSIVE | 条件比较、未知字段和下一需要的数据，不只展示分数差 |
| 固定核算 | 原批准、输入 hash、固定脚本／镜像、job、UNKNOWN／结果回执 | 数字核算结果改变评估；不证明方法复现 | 批准、开始、完成、用户 Action/resultCardId 与现实效果分层 |
| 用户行动／结果 | 原 Action、完成时间、resultCardId、来源及自报层级 | 更新承诺、经历、相关假设和原经验案例 | 新会话接回同一结果与未决条件，不重新创建一个任务 |

CT-7 部署、CT-9 Browser/外部应用以后扩 L0 adapter；CT-10 的 effect receipt 以后进入结果链。当前不显示假浏览器、假部署健康或外部写按钮。

## 5. Web：围绕判断和变化组织

保持四项主导航。记忆页以“已记录／待核实”为内容切换，变化经过与方法经验按需展开。不要把六种内部语义变成六个导航。

已记录项显示简明主张、来源类别、当前／历史状态、最近变化；“用户报告”“工具观察”“推断”可核对。“确认”明确是用户确认，不加独立实证勾。

待核实项显示可验证陈述、为什么与当前目标有关、主要条件／反证、真实调查状态和下一合法动作。第一次提出、调查中、受支持、被反驳、未定、到期分别显示；在旁边给“继续原调查”“补充材料”“理解有误”“不再参考／少提醒”等适用操作。

例子：

> 推测：缓存可能影响这次延迟。  
> 新日志提到了缓存，但还没有同条件对照。  
> **继续核对**　补充对照结果　理解有误

“继续核对”回原 claim 与原 Conversation/Mission。无原 Mission 时由当前原调查承接，只有需要持续委托时才创建原 Mission；不为每条推测自动复制任务。

### 5.1 就近纠正

入口附着于服务端定位的原 block/claim。短表单先显示“你在纠正哪一句”，收用户原话，再展示影响范围和原材料入口。明确解释错误时可直接记录，不强迫用户先填写复杂 Schema 或每次指定日期。

原材料错误、工作方向、使用抑制和提醒偏好在需要时分流。没有唯一 locator 时一次澄清；不默认屏蔽整份文档。保存后说明哪些判断需重核、哪些已重评，不能只有“保存成功”。

生成式 UI 继续由模型选择内容／顺序；claim ref 和控制资格由原 presentation catalog hydration。优先给现有 block 增可选、服务端绑定的 correction target，应用控件调用 typed service；不能用模型生成 URL 或将纠正伪装成业务批准。确需扩 action union 时仅白名单控制分支，旧客户端正文 fallback。

### 5.2 来源深读

网页快照、论文元数据／全文、PDF 物理页、实验条件和固定核算保留各自语义。原文与解释并排／分层；对比两个版本时显示确切修订。

UX-2 包含同页定位的实现和探针：可复用现有 Poppler／原件查看器，必要时在原文档服务增加有界的指定页渲染或页面摘录导航。原页渲染与 OCR／复杂表格是不同能力；不支持时明确缺口并保留原件，相关 Gate 不提前关闭。

## 6. HarmonyOS：同一认知，轻量处理

复用现有 GlobalMemoryTab、MemoryTimeline、AgentMessageBlocks、ConversationContinuity、ConversationWebSource、AttachmentViewer、MissionReadbackView 与 DraftStore。增加相同 claim/digest/locator DTO 和原服务调用，不另建本地记忆权威。

手机首屏是一项重要变化或当前判断；展开看依据、原版本和原因。默认按块纠正，避免依赖尚未验证的精确文本选区 API；长按选择有重复片段时仍须唯一定位。

“继续调查”打开同一 Conversation/Mission 和 claim；“补结果”回原 Action；批准仍在原 App 绑定服务。Web 上撤权／修订后旧手机控件先重读，服务端最终拒绝旧效果。离线仅展示带核对时间的缓存，保存草稿但不自动提交。

大字体、深色、长中文、输入法、读屏、返回、页定位和退出清私人缓存分别验收。HAP 与模拟器不替代目标真机；小艺／卡片只承接真实可用的最小摘要和 App 导航，不新增审批能力。

## 7. 首次使用与低变化场景

空项目先记录一条真实资料、问一个有价值问题；没有必要就不创建假设或委托。旧资料很多时先有界综合并标覆盖；后台未获模型许可时保留可用原始检索，不用空白摘要阻塞工作。

无重要变化不生成新整理消息或新假设卡。新证据真正改变判断时才展示简明差异：原来怎样理解、现在为什么变了、尚缺什么。停止提醒不删除认知历史；撤回纠正也不复活旧批准。

## 8. D1/D3/D5 完整旅程

| 时间 | 用户和 Agent 的真实行为 | 持久身份／结果 |
|---|---|---|
| D1 | 用户问论文方法是否适合项目；Agent 动态读可用元数据／原文／记录，提出可测试假设 | h1、原来源及条件、原 turn/Mission；未读全文保持未知 |
| D3 第一次变化 | 新 CSV 与论文 split 不同；Agent 识别不可比，可读条件或问缺失资料 | h1 新评估 INCONCLUSIVE；不是“论文被反驳” |
| D3 第二次变化 | 同条件实验出现反向结果；经原批准做固定核算；用户纠正先前自报性质 | h1 同一身份的反证与新修订；旧摘要／提案需重核；原核算回执 |
| D5 | 手机新会话继续：读当前理解和原因，补原 Action 结果；Web 回读 | 同 h1、Mission、Action/resultCardId；保持 REPORTED 和剩余未知 |

这是行为验收，不规定唯一工具链。先读 PDF 再读指标、先核对指标条件再取全文、证据足够直接结束都可合理；评分看原目标、条件、证据和真实下一步。
