# UX-2 R2：评测、开发顺序与首阶段 Prompt

## 1. 交付与依赖

推荐一个实施分支／PR 内按 A/B/C 检查，保持同一完整 UX-2 目标。必要时可拆可审查提交，但不把建表、界面或单工具 pilot 单独标产品完成。

| 内部检查点 | 前置 | 退出条件 |
|---|---|---|
| A1 F07／血缘／定位 | 当前 UX-1；原源与批准服务 | 原事务 guard、捕获／采纳 revision、通用 locator、历史回放、跨端 source DTO 和负例 |
| A2 纠正＋完整证据交互 | A1；Claim/Event 基础 | 一次纠正跨消费有效；Web/鸿蒙能读原来源、定位、比较和继续；原工具全部可用 |
| B1 综合与依赖 | A 的有效视图／版本 | Digest manifest、失效、增量、失败恢复、无变化零模型；原事实不覆盖 |
| B2 Composer 实接 | B1；原 ContextBuilder/Investigation | 两条真实上下文入口均消费有效记忆和未完成承诺；支持回原文；不固化工具顺序 |
| C 假设验证 | A 定义的稳定身份；B 消费 | D1/D3/D5 同一假设和任务，支持／反证／未定／到期、真实工具和原回执 |

F07 在扩大来源采纳／记忆使用前关闭；纠正 invalidation 不能等 B 才补。A 就定义 C 所需的认知身份，避免后续重建。CT-8 深入学习、CT-9 新工具不阻塞本 UX-2。

## 2. 冻结场景与失败反例

继承 UX-J04/05/06/09/10/14、CT-J 与 R1 并发／时间负例，不重命名历史失败为通过。以下新增开发回归题，不自称隐藏集。

| ID | 输入／旅程 | 必须观察的行为；失败反例 |
|---|---|---|
| M-J01 | D1 假设，D3 同条件反证，D5 新会话 | 同 claimId，修订和原调查可追；不是新建同名推测或重复旧建议 |
| M-J02 | 项目重点改变，原阶段原因仍有价值 | 旧综合不作当前方案，历史原因可追；不能抹去原验收或直接换永久目标 |
| M-J03 | 同根摘要、Artifact、Episode 各一份 | 不构成三源支持；递归／循环链 UNKNOWN，不无限展开 |

| M-J08 | 原来源撤权，同 SHA 换连接／ref；普通刷新 CAS 变化 | 旧候选新采纳被拒；新观察不复活旧 Capture／提案；普通刷新不当撤权；同命令回放只读原效果；未来原地重授另验 |
| M-J09 | 两端纠正／撤回与批准并发 | 一个合法控制次序；旧 hash/target 拒绝；已提交效果仍只有一个 |
| M-J10 | 无新事件跨有效边界 | 有效状态／hash／缓存失效，旧摘要不继续进入推理 |
| M-J11 | 用户 A 的私聊与项目 B 的相似记录 | owner/scope 隔离；跨项目迁移只产生带出处、待重验的新对象 |
| M-J12 | 旧客户端、未知 locator、离线草稿 | 正文／原对象 fallback；不猜最新相似项；恢复不自动提交 |

| M-J14 | 整理预览后材料变版，随后撤销 | 原 guard 拒绝过期效果；撤销不覆盖新的独立修改 |
| M-J15 | PDF 中部关键反证、重复段落、emoji | locator 不串句，裁剪不冒充无反证；能选择原页／原文继续读 |
| M-J16 | Card 被归档／用户确认，未新增证据 | 归档不变真假，确认不变独立实证；支持资格仍由原证据决定 |

## 3. Agent 质量与记忆消融

同一模型、工具、来源、初始任务、总模型／HTTP 预算和界面机制下比较：

- C0：当前有效检索，无新综合／假设生命周期。
- C1：增加 Memory Evolution/Composer，关闭持久假设验证。
- C2：增加稳定假设验证，综合按当前基线。
- C3：完整 UX-2。

四组都保留 Goal Reasoning、动态 Investigation、GenUI 和原批准。关闭某项认知能力不能改成固定流程，不能通过多问用户或删工具降低失败数。服务 correctness 修复属于所有组共同基础，不把修复权限 bug 的收益算成“记忆更聪明”。

| 指标 | 口径 | 放行要求 |
|---|---|---|
| 记忆效用 | 关键决策点是否正确使用既有条件／承诺／原因，并改善下一步 | C3 对 C0 配对报告；不能只报检索命中 |
| 纠正传播 | 纠正后不再错误复用的机会／全部暴露机会 | 工程硬负例全部通过；人评建议 ≥95%，报 n/N |
| 负迁移 | 错误／不适用记忆导致的新增错误决策 | 不高于基线；跨用户／越权硬例 0 |
| 假设辨别 | 支持／反驳／未定的语义与条件是否正确 | 不以状态 API 成功代替语义评分；不可比误判硬例 0 |
| 调查适应 | 新观察引起合理换工具／询问／结束 | 允许下一步集合评估，不指定唯一工具链 |
| 接续质量 | 找到原认知对象和任务，无重复批准／Action | 工程 100%；原 resultCardId、历史和未知可读 |
| 证据质量 | 引用支持关系、版本、根独立性、覆盖 | 元数据当全文、摘要当独立证据、推断当用户指令均为失败 |
| 成本／噪声 | 模型、工具、HTTP、UNKNOWN、用户打断分别计数 | 无变化零新增模型；关键条件改变不因降噪被忽略 |
| 用户负担 | 找原文、纠正、继续调查的时间／操作／重复解释 | 首次使用与复杂旧资料均测；不能只看满意度 |

延续原 24 条隐藏多轮题，由非实现者准备、双人盲评；新增场景公开后转开发集。至少 5 名目标用户、跨三类项目、相隔 ≥3 自然日；模拟时间只验证工程时态。模型裁判辅助，不等于独立人评；执行结果用原 SQL／回执核对。

真实模型使用新 campaign、冻结上限和逐请求账本；历史 UNKNOWN 不删除。预算未冻结前不启动正式评测，本轮调用 0。报告均分之外列错因、代价、覆盖和失败个案。

## 4. 可靠性、迁移和灰度

新增表／字段先验证空库重放、旧库副本升级和旧消息兼容，不操作真实数据库。旧 locator／来源无法识别时保留历史并禁止相应新效果；不语义猜测批量回填。

读写 capability 渐进启用；已有纠正、STOP、来源限制的消费 guard 常开，不因 UI flag 关闭而绕过。回滚可退投影和新功能入口，保留事件、旧回执和无效资格。Digest 可重建，L0 原文与 ClaimEvent 不当缓存清空。

检查沿用 npm.cmd test、tsc --noEmit、lint、隔离 E2E、harmony:test/build。新增数据库探针在导入 db 前绑定独立库；保留文件串行、Windows 进程清理和旧失败证据。目标设备、平台、生产和真实研究结果分开签收。

## 6. 必须先验证的架构假设

1. 三个新对象能覆盖稳定认知、追加历史和派生综合，不需要把原事实再复制一份。
2. 相关纠正可进入原 reuse hash，兼容旧空视图而拒绝旧效果；跨 scope 不误失效。
3. 原用户写锁、seq 和 lease 协调能承担纠正并发；锁顺序不产生新的死锁／丢更新。
4. 原工具步骤能承接编译和验证 leaf，累计成本与恢复不新增账本。
5. bounded 源图和按需原文能兼顾质量与成本；大资料下不靠遗漏反证“优化” token。
6. 双端 locator、页面阅读和请求恢复确实可用，不能由构建推断设备验收。

任何探针推翻假设时，在原模块内调整数据／服务方案并记录依据；不得用删掉工具、自主调查或多日接续来降低范围。
