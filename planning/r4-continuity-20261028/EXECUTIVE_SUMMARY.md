# Agent Continuity & Trust × Tool Ecosystem：审计与下一阶段方案

日期：2026-10-28（America/Los_Angeles）。代码基线：`1132f30ee149e42d5f9fce79219ba1d9ecf02ea3`，分支 `codex/r3-runtime-research`。本文档包是规划交付；业务代码、数据库和环境未改动。

## 推荐结论

建设一个能持续接手项目工作的 Agent：用户修改方向后，它能立即按新方向自主调查，保留仍有用的证据，淘汰失效建议，继续原任务；获得有期限和预算的持续调查授权后，能在用户离开时推进已许可的调查，在真正需要决策时再打扰用户。认知、工具、交互和原业务回执必须作为纵向能力一起交付。

**第一个值得实施的切片是 CT-1「改道后继续办完同一件事」**：

> 第一天要求扩功能；第三天改为“本周先保证演示稳定，先别增加功能”；Agent 自动调整调查方向，结合 PR-6 官方网页、项目原始记录和已有仓库线索，提出有依据的下一步。旧扩功能提案不能再确认。用户确认后继续原 Action/Mission；第五天在新会话打开时，能直接知道现在等谁、已有何种结果、接下来可以做什么。用户可以纠正、撤回和恢复原方向。

这一个切片同时接入有效意图、纠正、最小上下文协调、原提案失效、跨会话接续及双端动态 UI。**不把它拆成几轮只有建表或展示卡片的交付。** 持久化建议为一张用户指令事件表和 User 上一个序号字段；其他能力扩展现有 manifest、Mission、Anchor、Decision 和 AgentExperience。

## 当前已经有什么

- 动态 Investigation、GoalGap、模型选择展示结构、原 Action/Mission 确认及回执均有代码；不是等待建设的新框架。
- PR-6 已接 Search/Fetch、用户 URL、研究范围、覆盖、网页快照、费用预占、取消与原 Turn 恢复。
- 时态卡片关系、Decision 影响传播、Mission 等待/自动接续、Anchor 去重和停止、用户提醒预算已经存在。
- 已有 `AgentExperience` 的候选→影子→用户激活及撤销机制；已有 GitHub 公开 commits 的显式刷新和 Focus 缓存观察。
- 现有缺口集中在：会话限制是无作用域的字符串；跨会话缺少可修订意图入口；各条读集没有统一绑定有效意图；真实结果尚未形成条件充分的经验；Anchor 和提醒政策未统一。

PR-6 是**实现检查点，尚未整体放行**。记录中的冻结对照仅完成 11/48 个 arms；最终全量回归、Web E2E、独立质量评分、完整设备旅程仍待完成。本轮未重跑这些检查。

## 下一批工具怎么衔接

第一项专用 Tool 选 **GitHub/CI 固定 revision 观察**：沿原 `SourceConnection` 增加具体 commit 的 checks、失败 job 和有界 diff，证明“这次改动是否解除当前目标的阻碍”。已有 commits 不再作为新功能计算。随后交付文档页/节/表格深读；实验指标与固定脚本验证形成下一条 N6 闭环；论文、部署观察、浏览器和外部应用按各自旅程接入。

持续调查采用原 Mission 的显式调查委托及原 worker，不新增 Runner。工具是否可用、是否可外发、是否可后台调查、是否可通知、是否可外部写入分别授权；一次范围授权内的合法只读调用由 Agent 自主选择。

## 本轮相对基线的关键修正

1. 纠正不另建一套事实库；用户指令事件只记录“用户要求怎样协作”，事实仍留在原 Capture/来源/时态关系。
2. 不把所有变更都变成待确认提案。明确且范围唯一的工作方向、停止和表达偏好可直接生效并提供撤回；共享事实修改、业务写入和授权扩大仍沿原确认机制。
3. 把**意图失效检查接到调用前、回答发布前、确认事务和恢复前**，不能只给旧卡片加一个 stale 标签。
4. 将“已授权任务应继续推进”和“关键变化不能被静音漏报”列为质量门槛，防止保守策略虚获高安全分。
5. 单次真实结果可以立即影响当前判断；多次结果才支撑可复用方法。复用现有经验激活制度，不因样本不足阻止当前任务吸收新证据。
