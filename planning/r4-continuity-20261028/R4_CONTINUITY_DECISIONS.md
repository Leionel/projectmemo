# 架构裁决、产品选择与授权边界

> **R1 定向修订 · 2026-10-28（Asia/Singapore）**：调整D01/D04/D08并新增§6的五项明确裁决及实施探针风险；其余工具顺序、原授权和完整CT-1目标保留。

## 1. 本方案已作出的推荐

| 决策 | 推荐结论 | 技术依据与真实增量 |
|---|---|---|
| 是否增加第二个Runner/Planner/记忆库 | 不增加；原Investigation、Mission、Decision、Temporal Ledger、AgentExperience各管原职责 | 当前持久执行/动态loop/影响job已存在，缺的是相同上下文的贯通 |
| 意图存哪里 | 一张AgentDirectiveEvent + User.continuitySeq；有效视图按scope计算 | 现有pinned缺范围/替代/期限；事实卡片与私人指令authority不同；一个用户流即可保证原子序号 |
| 是否另建Correction表 | 不建；纠正作为typed指令事件，目标指向原判断/来源 | 用户反驳与客观事实不同；事实变化仍走原Capture/关系/服务 |
| Resolver放哪里 | 原Conversation/workspace的薄模块，由Mission/D1/D2共用纯读入口 | 解决复用，不再起一个长期记忆Agent或全局上下文服务进程 |
| 依赖检查 | 精确read-set即时guard + 原ImpactJob异步有界投影 | 正确性不能等待worker；无关scope不失效；不做全图重推理 |
| 什么时候应用用户新目标（R1） | 通过Admission的有界字面工作指令直接生效；模型解释需候选或精确确认；共享Project/Mission事实修改仍原确认 | 来源认证、原话存在、解释正确分别证明；scope/期限不能暗中扩大 |
| 第一纵向切片 | CT-1“改道后继续办完同一件事” | 同时改变调查、旧提案、跨会话接续和双端交互，可用现有PR-6验收 |
| 第一新增Tool | 固定SHA的CI观察；紧接文档深读 | commits/连接已存在；CI最短填补工程实证；文档保证非开发领域价值 |
| 是否新增Registry | 扩ToolSet descriptor + actor adapter能力过滤，不建Registry表 | 权限/预算身份已有；只补来源、effect/replay metadata |
| 持续调查是否本阶段做 | 做CT-3，原Mission中增加有界调查委托 | 不依赖所有Tool建好；一次scope/期限/总预算批准后自主推进 |
| 结果经验怎样升级 | 当前结果立即用于当前判断；复用方法沿原SHADOW/ACTIVE；扩结构化适用条件 | 不把“两个工具序列成功”当真实方法效果；也不等待长期经验激活才响应新结果 |
| 生成式UI怎样扩 | 共享可选continuity投影与单类typed语义panel，原catalog/动作绑定/renderer | 保留模型组织信息能力，不增加六套表单或客户端业务规则 |
| 不同来源怎么计信任 | authority、证据层级、适用性、语义支持、来源独立性分开 | 一个高置信分不能授予授权；多个同根摘要不能冒充独立来源 |

这些是可以据以进入下一轮实施的技术选择，不是本轮已完成的代码。

## 2. 实施前应确认的产品政策

以下均给出默认推荐；本轮用该推荐完成方案，不为等待答复停止规划。用户下一次授权CT-1时可一起确认其相关项。

| ID / 问题 | 推荐默认 | 何时需要定稿 / 未定时处理 |
|---|---|---|
| D01 明确自然语言工作指令是否直接生效（R1） | 采用Intent§2A四条件和五种准入结果；有界字面规则或精确确认才active，模型分类不能产生永久目标/扩权 | CT-1。直接生效覆盖与误准入一起验收；不能以只做UI命令/shadow作为最终交付 |
| D02 临时目标与正式项目目标的关系 | 私人工作方向可先改；共享Project.goal/截止日/验收条件沿原预览确认 | CT-1。新方向不自动降低原成功标准，UI展示差异 |
| D03 作用域默认 | 明确指代项目则本项目；明确“这次”则turn；一般会话表达先conversation；全用户偏好只显式提升 | CT-1。不自动跨项目总结偏好；明确授权的跨项目私人偏好可复用，不能永久禁止该能力 |
| D04 到期/撤回旧目标是否复活（R1） | 半开有效区间；事件epoch+validitySegment；撤回/替代不复活前版；回原正式目标须重新协调 | CT-1。无事件跨边界亦即时失效；历史asOf不能用于效果确认 |
| D05 主动调查的授权形式 | 一次具体scope/工具/期限/总预算/通知规则预览，之后合法只读步骤自主执行 | CT-3。不以Search或FOLLOW许可代替后台费用授权 |
| D06 打扰频率与安静时段 | 沿已有USER日预算和时区（当前默认3次）；digest不算系统打扰；无紧急例外自动越过静音 | CT-3。先应用内摘要，系统推送需现有通道许可；默认必须同时测false silence |
| D07 结果案例的自动参考 | 单次案例可作为注明条件的历史类比；长期过程建议沿原激活制度；不自动写永久事实 | CT-8；CT-1当前任务结果可立即重评，不受此等待 |
| D08 明确归入项目的研究副本在原许可撤回后怎样处理（R1） | 明确独立project用途与原抓取授权分别校验；原许可撤回不必删除全部历史。但后来覆盖该派生链的SUPPRESS_USE必须阻止新认知消费，不被发布许可豁免 | CT-1。用途/抑制/权限分开；旧未知链只能作为安全定位线索，不作为独立证据或新操作依据 |
| D09 “不要记住”与“删除”的默认区别 | “不要再用”立即SUPPRESS_USE；明确删除启动内容/索引/派生清理；审计只留最小无内容回执 | CT-1先抑制未来使用；完整清理/备份保留期在治理切片前定稿，不宣传软删除为删除 |
| D10 审计/备份留存期限和导出范围 | 不在代码里擅自定永久保留；由产品政策指定最短必要期限、用户可见范围、备份轮换 | 内容硬删除发布前必须定。当前仅设计接口与传播范围，不操作真实资料 |
| D11 首批CI和文档顺序 | CI先、文档紧接；若实际样本无CI可调换 | CT-2前据可用真实项目验证，不需要重开整轮泛化研究 |
| D12 语义门槛与独立评审资源 | 开发pilot后、隐藏集运行前锁定；非实现者双评审；当前给90%等建议目标 | 真实质量验收前需评审与预算；工程实施可继续 |
| D13 退出登录与持久委托 | 活动Turn按session终止；明确批准的长期委托可按其到期/撤销规则继续，退出时可查看或停止 | CT-3；用户未认可离线持续委托语义前不在后台启用该模式 |

## 5. 未决技术假设与证伪条件

- User行短事务可承载当前SQLite单用户指令序号：需并发探针；若写争用实测显著，才增加scope cursor，不先造复杂分片机制。
- 原Turn/Step JSON容量足够首切片：需基于真实最大会话测量；超过边界先做关键span/指针分层，不靠无界扩上下文。
- 原服务读集可以增量加入continuity guard：若某条实际效果路径未覆盖，必须补该路径后才放行，不能在UI禁用按钮收尾。
- 文档parser/沙箱可在目标环境运行：没有平台证据前保持对应Gate开放，不以本地工具可用推断ECS/HAP具备同能力。
- 有效指令/经验改善长期质量：由配对隐藏评测证伪；若只增加费用/打扰，应修策略或停该扩展，不将用户目标缩小到指标易通过的题型。

本轮规划完成不等于上述假设已验证；下一轮实施范围可从CT-1明确开始，无需再次询问已由代码回答的架构问题。

## 6. 【R1 新增】定向修订裁决与探针风险

| 合同 | 冻结裁决 | 仍须用实现探针验证 |
|---|---|---|
| Directive Admission | 源认证/本人指令/范围期限/语义效果分别可核查；字面有限指令直接应用，模型猜测留候选，实质歧义一次澄清；永久目标与扩权必须精确确认/原授权 | 自然中文的否定/转述/条件识别边界与直接生效覆盖率；不能只测quote存在 |
| In-flight | 同一原Turn增加coordination子状态；generation隔离认知、lease隔离执行者；先失效、有限drain、再激活最新g；派发权与结算权分开 | 原mutateTurn/baseVersion、同步token、停止heartbeat和恢复CAS兼容；SQLite多进程竞争及丢回包 |
| 缓存/费用 | 跨g只复用重新校验的原始成功观察；旧模型不可复用；UNKNOWN指纹跨g稳定；根预算不重置 | provider是否可查询原请求；不能查询时UNKNOWN预占长期存在，不能靠猜测释放 |
| Suppression & Provenance | 全关键消费路径使用同一策略hash及来源闭包；未知/环链不增信，允许另查原文；ACTIVE经验及已发布Artifact不豁免后来的明确使用抑制 | 旧卡片/Artifact/经验的根来源覆盖、块级映射和查询开销；断链时仍能推进独立调查 |
| Time & Scope | UTC+原时区、半开区间、相关scopeEpoch+validitySegment；缓存到边界失效，guard不依赖新事件或定时器；迁移双scope原子提交 | 端点最终guard时钟、DST/时区变更、跨项目CAS/锁顺序和时钟回退行为 |
| CT-1组织 | 一个实施PR内A指令保护→B认知改道→C跨会话双端完整回执；只有最终纵向闭环算完成 | 原Mission恢复、Action完成/resultCardId与D5接续在同一实现可复现，不能以中间checkpoint签收 |

R1全部是本轮规划裁决，未运行上述业务探针。若验证显示原预算/事务无法承载，应修正实现与记录Deviations；不减少CT-1的动态调查、Goal Reasoning、PR-6、原授权、AgentExperience或生成式UI能力。完整内容删除、真实模型预算、外部账号与生产操作继续按原专门授权边界，不因本次修订启动。
